## 如何阅读

- **已实现／历史已验收**：代码与既有证据存在；本轮最终复验以全面复核报告为准。
- **本轮本地已验收**：回归、独立课程运行及限定范围故障/压力测试通过；最终提交与云 CI 另行验收。
- **未纳入范围**：明确不由当前校招项目保证，不增加空壳组件来制造技术点。

全量问题判定见 [28 项复核台账](review/2026-09-12/assessment.md)，本轮结果见 [交付与验收](review/2026-09-12/acceptance.md)，业务判据见 [A01—A28](implementation/acceptance.md)。既有 [业务验收](../verification/2026-09-10/summary.md)、[Git 与云 CI](learning/from-zero/verification/2026-09-12-git-publication.md) 都保留各自测试时间和适用提交。

## 不做或尚无证据的能力

1. 不包含真实设备协议适配、无人机路径规划、资源优化、自动挑选执行方或全局优先级调度。当前是操作员选实体后的可靠下发与执行跟踪。
2. 没有 Kubernetes、跨机时钟、跨地域或多 broker 故障转移的实测保证。同机 1/3 个 Entity 实例的有限对照已经完成，但不代表跨机扩容或生产高可用通过。
3. 当前已包含个人账号后台、管理员本机初始化/恢复、操作员管理与本人改密；不包含公开注册、邮箱/短信找回、单点登录、TLS/mTLS 或生产密钥托管，不包装成完整 IAM 平台。
4. 已完成墓碑与结果为幂等证据，暂不自动删除；派生索引消除了热路径全历史扫描，但不解决无限运行时的磁盘增长。规模扩大前需要有证据的保留/归档边界。
5. 2026-09-12 六类混合实测使用 10000 实体、10 来源，100/500 events/s 各 30 秒；500 档实际约 499.90 events/s，ACK p99 1.449ms，抽样可见 p99 3.053ms，错误/遗漏/最终 lag 为 0。它仅覆盖指定状态链路，不是最大容量，不覆盖网关磁盘、任务执行、订阅扇出或搜索查询并发。本次百万实体试验已完成并保留失败边界，工具有独立资源上限、完整预热和失败报告；当前尚无百万通过结论，不从一万实体结果外推容量。
6. ES 只读投影具有延迟；任务动作遵循 MySQL 事实。PIT 保障一次搜索视图，TaskService 的单页一致读不等于跨多页长期快照。

面试时应以“实现了什么、如何复现故障、结果证明到哪里”介绍项目，不用组件数量或代码行数替代这些证据。

补充恢复边界：故障演练以 `start --wait` 恢复原容器，脚本比较 Kafka/Redis/MySQL 的容器身份；带 Search 覆盖参数的 MySQL 实测恢复后命令参数不变。容器丢失时明确失败，重建必须按原完整配置由操作者处理。见本轮 N10 排错记录与验收追加。
