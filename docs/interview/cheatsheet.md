# 面试速查卡（一页）

> 面试前 10 分钟只看这一页。详细版见 [interview-prep.md](interview-prep.md)。

## 30 秒自我介绍

> 一个多源实体实时协同与可靠任务调度的平台：六类异构来源统一接入，状态可查可订阅，并且能在指定实体上可靠下发巡检任务。Go 写的，八个小程序，中间件 Kafka + Redis + MySQL。重点全放在故障下数据不丢不重：消费中途崩溃、执行方断线、消息保留窗口被清掉，都有真实跑过的恢复验证。

## 3 个能讲透的点（每个 3 分钟）

1. **至少一次 + 消费端幂等**：位点提交严格晚于副作用；版本/墓碑判定放在 Redis Lua 里原子完成（旧版本忽略、同版本同内容算重复、同版本不同内容报冲突）。
   → `internal/state/entity.go:26`、`internal/bus/kafka.go:158-170`
2. **Outbox + 租约投递**：任务/审计/Outbox 同事务；分发用 `FOR UPDATE SKIP LOCKED` + 租约 + 有界重试 + DLQ。
   → `internal/tasks/service.go:147-152`、`internal/tasks/dispatch_worker.go:39,47`
3. **边缘持久化**：来源侧 bbolt 待发送队列（只推进已确认水位）、执行方侧持久 inbox（先落结果再回报），有真实强杀验证。
   → `internal/edge/queue.go:24-29,300-323`、`internal/edge/inbox.go:290`

## 3 条边界（主动说，别等着被问）

- 数据源和执行方是**模拟的**，无真实设备、无路径规划。
- **单实例、本机 Docker**；无 TLS、无用户体系，凭证是机器令牌。
- **搜索链路未装配**（组件与测试已有，缺进程/配置/消费者）；整个工程尚未提交 Git。

## ADR 一句话清单

| 决策 | 一句话 | 换掉它的条件 |
| --- | --- | --- |
| 至少一次 + 幂等 | 跨系统没有精确一次，所以让副作用幂等 | 副作用变成单系统内事务时 |
| Outbox | 同事务写事实与待发事件，避免双写窗口 | 团队已用事务消息中间件 |
| Redis Lua | 先读后写有窗口，锁又太重 | 视图能被单进程独占 |
| bbolt | 断网时不能依赖中心，要本地事务文件 | 需要多进程共享/复杂查询 |
| 租约 + SKIP LOCKED | 互斥解决不了"恰好一次"，恢复要能靠一条 SQL 推断 | 投递量远超单库承载 |
| CDC 做搜索 | ES 是可重建的只读投影，写链路不依赖搜索 | 已有 Debezium/Connect 生态 |
| 签名游标 + 抽样历史 | offset 深翻页会漂移；历史是轨迹不是全量 | 产品需要"跳到第 N 页" |

## 8 个必答问题的一句话答案

1. **重复怎么办？** 三层幂等：事件级 `event_id`+版本（Lua 原子判定）、回报级请求哈希去重、执行方持久幂等键（`effect_count=1`）。
2. **丢失怎么办？** 提交点晚于副作用 + Outbox；宁可重放不可静默丢。
3. **消费中途崩溃？** 未提交部分重放，靠幂等兜住；`Generation` 做代际围栏。
4. **为什么不用 exactly-once？** 副作用跨 Redis/MySQL/本地文件，Kafka 事务覆盖不到，跨系统精确一次是伪命题。
5. **Lag=0 等于完整吗？** 不等于。保留窗口被清后从保留起点读，Lag 也会归零，但中间事实已丢；所以要独立期望清单校验，对不上拒绝切换。
6. **吞吐多少？** 本机 100/500 events/s，ACK P99 6.0/3.9 ms，**不代表容量上限**。
7. **多租户？** 租户取自可信身份而非请求参数；游标 HMAC 绑定租户与筛选条件。
8. **你怎么保证对着？** 真实依赖集成测试 + 真实进程强杀 + 故障演练输出；关键不变量我自己读实现确认。

## 「这是你写的吗」

> 整体设计和这版代码是在 AI 助手协助下完成的。我负责定边界、做选型、判断哪些测试算通过，以及逐处核对不变量——比如"投影必须用严格消费"是我发现 `ConsumeStrict` 写了但生产路径没接线之后提出要改的。所以任意一处都可以问我为什么这么设计、代价是什么、还有什么没做完。
