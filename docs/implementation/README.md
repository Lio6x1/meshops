## 本次定义的交付范围

| 里程碑 | 完成条件 | 包含任务 |
| --- | --- | --- |
| 首个可用版本 | 人员、无人机两类接入；查询/订阅；一种 inspect 可靠任务闭环 | S01—S04、S06—S07及T01—T04/V01的两类型子集演示 |
| 校招核心完整版本 | 六类实体都能接入/查询/订阅；能力限制正确；历史抽样；两条链路故障验证与实测报告 | S01—S08、T01—T04、V01—V03 全部验收 |
| 按需增强 | 动态多实例、etcd、Pub/Sub、复杂检索、Web | 不计入以上完成条件，另立需求 |

核心版本中的六类是有限实现：person、drone、vehicle、robot、sensor、facility，每类一个明确的模拟格式，不接真实硬件；前四类可声明 inspect，后两类只提供状态。这里把此前“其他类型逐步增加”具体化为 S05 的交付，任务能力仍保持一种。P4/P5 不进入本次执行清单。

首个可用版本是阶段演示，不代表相关任务或验收项全部完成。T03的完整A20依赖S05四类补齐；V01也须全部命令可用才完成。按默认顺序开发会先完成S05；为了提前演示两类型而交错开发时，进度明确记录“子集完成”，不提前勾选完整验收。

## 给接手 AI 的协作方式与提示词

当前默认是辅导模式：先查看学习记录、当前实验或Lxx课卡及详细讲义，讲清小单元、定位文件、逐段解释示例，给出输入输出和验收方式。用户只说“继续”时延续学习单元；明确要求“这一块你写”时直接完成该范围并讲解。初始单元是F01建最小模块，F05后进入L01骨架导读，L02后进入L03配置读取。

下面是用户明确选择让AI直接开发时可复制的任务说明；默认辅导时不要自动执行整份实现计划：

> 在当前 MeshOps 仓库开发。先阅读 docs/implementation/README.md 和它列出的规格、计划及验收矩阵，再检查 git status 和实际代码。保留已有用户修改、四服务架构、项目名和 P0—P5 阶段，不重新生成 app 业务文件。当前先实现状态计划中第一个尚未完成的任务，按任务内的测试、实现、验证步骤执行；每完成一个任务，将实际测试命令、结果与证据写入进度记录。已有 UNIMPLEMENTED 骨架测试在对应功能实现时替换为真实验收测试，不得仅删测试。不要把模拟器占位、测试未发现用例、脚本空跑、依赖没启动或跳过检查报告为成功。新增依赖只按技术选型加入实际使用的包并锁定版本。发现确定的规格矛盾时，记录具体冲突和最小解决方案；普通实现细节自行处理。用户要求全项目时，依次完成 S、T、V 必选任务，以验收矩阵为完成依据；用户只指定任务时，完成该任务及其必要前置工作。Git 提交、推送和破坏已有数据按用户授权执行，不由本文档自动授权。

以后在本对话里说“从 S01 开始”也使用同一份规格，默认先进行S01当前小练习；说“直接帮我完成S01”则按任务代写并讲解。每次无需重新讨论项目背景。
