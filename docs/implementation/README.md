## 后续协作规则

先读用户当前要求、Git 状态、实际实现和对应课程。修复或增强已存在的工程，不按旧计划重新生成骨架。辅导时从用户确认的学习步骤继续，给完整参考文件、说明、命令、预期和测试；维护时按受影响阶段同步代码与讲义。用户当前请求优先，不因为历史记录写着“Z00”就中断正在进行的工程工作。

明确区分实现存在、测试实际通过和用户已经理解。依赖未启动、用例跳过、脚本未执行不能写成通过；历史验收只证明记录的提交与范围。学生进度不能用 AI 完成量代替。
