## 约束

- 中文项目名和多源实体协同定位保持不变；车辆等仅作为仿真实体示例。
- 当前阶段完成说明、边界和骨架，不代替用户实现业务。
- Proto 和 SQL 作为待业务验证的 V1 设计基线；补齐累计 ACK、执行回报、订阅同步与历史查询接口，不强制增加多源组件融合。
- 不添加中间件，不提交 Git，不启动或清空已有服务和数据。
- 保留已有文档路径、章节主体、四服务架构及原分期；只对确认的范围调整和具体设计矛盾做局部修订。
- `docs/entity-catalog.md` 的六类实体属于平台设计范围；其中园区、配送等场景仍仅供参考，不代表已选定行业业务。人员与无人机是首批实现来源。

## 本次契约约束

- Ingest 保留双向流；上传代际与本批起始序列独立于实体版本，同批事件序列连续。
- Entity 保留现有字段号，增加可选人员/传感器/电源组件、任务能力目录和实体生命周期；不实现多来源融合。
- Subscribe 增加快照帧、同步结束、增量、删除和视图代际；废弃单一全局 snapshot_version。
- ExecutorService 注册在 Dispatcher 进程，负责执行方监听任务；结果通过 TaskService.ReportTaskStatus 回报，避免新增第五个中心服务。
- 任务 execution_key 在重试中不变；command_id 标识逻辑命令，dispatch_id/attempt 区分发送尝试。取消请求不直接等价于已经停止。
- SQL 增加单独 002 迁移，保留已有 001；不执行用户数据库迁移。
- 验证只覆盖契约、骨架错误行为和生成/构建流程；测试通过不表示业务能力已经实现。
