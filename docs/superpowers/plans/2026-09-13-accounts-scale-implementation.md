# 账号、容量验证与最终回归实施计划

> 执行：使用 test-driven-development，独立子系统按 dispatching-parallel-agents 分工，主任务复查接口、整合、运行验收并同步课程。用户已明确要求开始执行，现有授权包含已讨论方案。

**目标：** 交付个人账号完整闭环、百万实体实测与有证据的写入优化、全功能回归、教程和目录收尾。

**架构：** accounts 模块接入现有网页网关与 MySQL；个人身份通过数据库解析的不透明会话令牌进入 gRPC。状态规模工具使用隔离 Compose，参数化现有真实验证器。

**技术：** Go、MySQL、Argon2id、Cookie Session、gRPC、Vue、现有 Kafka/Redis、Docker Compose。

**规格：** [接口与验收设计](../specs/2026-09-13-accounts-scale-design.md)。

## 全局约束

- 用户自行设置初始管理员密码，12—128 个 Unicode 字符且最多 512 字节；Argon2id 初始参数 64 MiB/3/1，16 字节随机盐、32 字节结果；哈希并发有界。
- 根业务与阶段教材分别同步，源码注释中文；不提交密码、真实令牌或学习数据库。
- 百万实体为基数，不表示百万 QPS；独立资源、硬时限、如实记录失败。
- 工作目录 `.worktrees/account-scale`，共用只读依赖与构建缓存；最终验收后整合到 main 并清理临时工作树。

## 1. 账号后端与可信个人身份

文件：新增 internal/accounts、migrations/005_accounts.sql、cmd/account-admin；修改 internal/platform、internal/app/run.go、internal/web、cmd/web-gateway。

- [ ] 先以密码一致/不一致、独立盐、超限编码与输入、错误泄露、用户名冲突和认证版本测试得到失败结果，实施哈希与账号事务。
- [ ] 实现规格中的全部 HTTP 接口和管理员初始化/本机重置命令；标准输入读密码，启动不覆盖账号。事务内写账号审计，管理员不能被操作员接口禁用。
- [ ] 个人会话接线到 RPC 身份，验证无法靠请求伪造 actor；创建/取消/重试任务的现有审计取得个人 ID。
