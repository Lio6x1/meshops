# 个人账号与百万实体容量验证

用户已确认精简账号范围、Session、Argon2id、管理员自行设置初始密码，并在本次明确授权恢复百万实体压测、补测试、全功能回归及清理。此文将既定需求落实到工程，不再次要求重复确认。

## 账号边界

新增账号模块，复用现有 MySQL、HTTP 网关与角色权限，不拆出新的账号微服务。初始管理员由部署机器上的专用命令设置用户名与密码；密码通过标准输入读取，不作为命令参数、日志或永久明文文件保存。启动与升级不覆盖已有账号或密码。无需公开注册、邮件、短信、第三方登录或分库分表。

管理员创建操作员、分页查看账号、禁用/启用操作员、重置操作员密码；个人修改密码。账号不可物理删除，初始管理员不可通过操作员管理 API 禁用或改角色。创建与重置后的操作员必须先改密码；初始管理员自行设置的密码不强制立即再改。

Argon2id 使用 golang.org/x/crypto，独立 16 字节随机盐、32 字节派生结果；初始采用 64 MiB、3 次迭代、并行度 1，记录参数并严限解码后的参数范围，防止恶意编码导致无界内存。密码为有效 UTF-8，12—128 字符且最多 512 字节，不裁剪密码或静默截断；用户名为 3—32 位小写字母/数字/下划线/短横线，不将大小写重复作为不同账号。错误提示不区分不存在和密码错误；限制登录速率与同时进行的昂贵哈希数。成本需实际测试，过载返回明确错误，不阻塞全站工作。

账号表保存稳定 user ID、tenant、username、displayName、role、enabled、mustChangePassword、password_hash、认证版本与时间。账号管理审计保存操作人、目标、动作和时间，不保存密码、盐前的原值或令牌。密码变更和禁用增加认证版本，并使旧会话失效。

浏览器仍使用 HttpOnly/SameSite Cookie 和 CSRF。浏览器会话在网关内存中，重启需重新登录。每次有效登录生成独立的随机内部会话令牌，数据库只保存其 SHA-256 查找哈希、账号/认证版本与到期时间；网关把该令牌用于内部 RPC，浏览器只收到另一随机 Cookie ID。平台鉴权在可信机器令牌之外增加数据库会话解析，得到真实 user ID、tenant 与 role，原任务/取消/死信审计据此记录个人身份。禁止把客户端随意传的 actorId 或 role 当作可信身份，不自创签名令牌格式。

机器来源/执行方/内部任务服务仍沿用原凭证；个人会话只允许 operator/admin 权限。账号模式显式启用，在成品及新课程中必须启用；旧阶段的访问码模式只用于阶段兼容，最终部署不能因配置错误静默退回共享访问码。查库异常拒绝请求，不能降级成默认身份。禁用/改密/重置/注销也取消该用户当前网关上的 SSE，后续 RPC 验证到期与认证版本。

## HTTP 接口约定

沿用 JSON 错误格式与 CSRF；成功响应不含密码哈希或内部令牌。

| 接口 | 输入与输出 |
| --- | --- |
| POST /api/session | `{username,password}`；返回原 session 字段并增加 username、displayName、mustChangePassword |
| GET /api/session | 当前会话，同上 |
| DELETE /api/session | 注销，204 |
| POST /api/account/password | `{currentPassword,newPassword}`；成功 204，清会话后重新登录 |
| GET /api/accounts?limit=20&after=ID | admin；返回 `{accounts:[...],nextCursor}`，按稳定 ID 游标分页 |
| POST /api/accounts | admin；`{username,displayName,password}`，只创建 operator，返回账号对象，201 |
| PATCH /api/accounts/{id} | admin；`{enabled:boolean}`，目标只能为 operator，返回账号对象 |
| POST /api/accounts/{id}/reset-password | admin；`{password}`，目标只能为 operator，204 |

账号对象字段 id、username、displayName、role、enabled、mustChangePassword、createdAt、updatedAt。tenant 来自可信会话，不接受用户传入覆盖。强制改密状态仅允许 session 查询/退出和个人修改密码，其余 API 拒绝。前端添加账号管理与个人修改密码入口，旧角色选择与访问码表单退出成品流程。

## 百万实体与高并发写入

恢复原规模草案，百万表示不同实体总数，独立于每秒事件速率与连接数。六类比例与十来源保持；预热必须核验全部实体身份/类型/版本，不以抽样代替百万初始化成功。提供 1 万/10 万/100 万实体参数和不同总速率，不把超时、OOM、供压不足或采样遗漏包装成通过。

采用专用 Compose 项目/网络/卷，无新增公网端口，保留固定资源限额、硬时限与采样。先在 1 万实体增加写速率识别吞吐瓶颈，再增加实体基数验证注册表、初始化和状态存储成本。百万初始化成功后再执行有界流量阶梯；失败先分析资源与阶段，不能凭估算宣称容量。

瓶颈必须有 profile/资源/队列/数据库指标等证据，优化不得绕过鉴权、版本校验、持久 ACK、历史预算或任务事务。维持当前单实例边界，允许针对已证实问题改批处理、热路径算法或有界并发；不引入未经验证的分库分表、多副本或复杂调度。
