## 过程中发现并解决的问题

1. **正常退出与上传结果竞争**：模拟器 duration 到期，上传协程返回 DeadlineExceeded 可能被误当成程序失败。只在控制上下文本身结束时归一化正常取消/到期，保留鉴权和协议错误；补了取消竞争、到期 join 回归测试。
2. **旧轮询覆盖新状态**：后台较慢 GET 可能晚于 PUT 后刷新返回。使用请求序号忽略旧结果；页面仍等待实际心跳应用状态。
3. **随机点位遮挡**：初版基准位置哈希可能使人员、车辆与设施重叠。六类演示实体改为分开的两行三列基准位置，移动半径约39m，固定设备不动；10个代表版本包含版本上限的间距/边界测试通过。前端继续使用真实坐标，未用像素偏移掩盖位置。
4. **并行编译内存不足**：完整课程和小步骤同时编译时，Windows linker 报 cannot allocate memory，小步骤首次在 Z11-01 失败。保留失败记录，待整课结束后以 `GOMAXPROCS=2`、`GOFLAGS=-p=2` 重跑五个小步骤全部通过。不是跳过失败阶段，也没有改业务代码。
5. **静态检查缓存目录不可写**：默认系统用户目录受沙箱限制。改用工作区中的 `STATICCHECK_CACHE`，保留第一次失败日志。该环境设置不改变分析规则。

## 本轮边界

地图覆盖固定演示区域，不是地图导航、路径规划或测绘系统。开关控制模拟数据源上报，不控制任务执行器进程。单个来源绑定多个实体时一起生效；当前清单是一来源一实体。批量切换非事务。目标模式持久化，心跳只短期存活，不声称进程有心跳就代表上传健康。Redis 故障时暂停，恢复后继续读取目标；仍是单机演示环境。

本轮没有重新做全平台容量压测或跨机故障测试；旧版本完整 CI 记录仍只证明对应旧提交。
