# 从零课程：完整参考代码交付标准

用户要求：**即使不独立编写实现，只按课程顺序复制参考代码、执行给定命令，也应能从空目录完成约定项目的全部功能。** 本标准适用于[新教学路线](from-zero-roadmap.md)的每个单元。自己尝试编写是可选学习方式，不是获取答案或继续课程的前提。

## 完成的含义

课程包含两条同时成立的要求：代码可以按步骤复现，讲解让学习者理解为什么这样做。完整参考实现必须覆盖每课必需内容；附加变式练习不承载后续课程必须依赖的功能。

“可复制”包括文件、依赖、配置、数据、生成和运行步骤，不只是几段核心函数。不要求学生自己猜遗漏的函数、搜索未给出的中间件接法或自行拼接不兼容片段。安装依赖和设置本机目录仍需要执行，但必须给出明确操作与验证方法。

完整功能以[原技术契约](../implementation/contracts.md)、[运行要求](../implementation/operations.md)和[A01—A28验收](../implementation/acceptance.md)为准：六类实体接入、统一状态/订阅、可靠补传、历史、inspect任务/执行跟踪、取消/超时/死信、身份隔离及工程验证。不能在结尾只交付一个能查内存数据的演示项目。

## 每课必须交付的内容

| 项目 | 具体要求 |
| --- | --- |
| 起始状态 | 指明依赖哪一课的完成版本，当前目录、已有文件和需运行的依赖；不使用尚未创建的结构体/方法 |
| 本课目标 | 描述一个具体功能或工程变化，给正常与错误输入，以及本课结束可观察的结果 |
| 文件清单 | 明确新增、替换、移除哪些文件；每个文件说明用途与相对工程根目录的路径 |
| 完整参考代码 | 所有手写新增/修改文件提供本课结束版本的完整内容或可下载原文件；课堂可分段讲，复制时不需学生拼接省略段 |
| 生成代码 | 说明哪些由工具生成，给固定兼容版本、完整命令、运行目录与预期输出文件；不必把生成文件逐行讲解，但最终检查点必须可构建 |
| 依赖与配置 | 给锁定依赖、配置文件、Compose/启动方式、迁移与seed；测试凭证给可重复操作的本机生成/设置步骤，不藏在教师个人环境 |
| 代码解释 | 逐段讲语法、参数、返回、调用顺序、错误分支、并发与持久边界；用本课输入推演，不只复述函数名 |
| 操作命令 | 以用户PowerShell环境为主，给精确工作目录、生成/构建/运行/测试命令；多终端标明分别在哪运行和如何停止 |
| 输出与验证 | 给成功/失败样例及检查方式；涉及跨服务、数据库或消息队列时提供真实集成验证所需接线与断言 |
| 排错 | 给可定位的常见错误、原因及修复动作，帮助判断是环境问题、复制遗漏还是代码行为不正确 |
| 对照版本 | 每课保留一个可获取的完成检查点或按顺序应用的完整文件集合，能与用户代码对照；不得依赖未提供的本地修改 |
| 可选练习 | 给参考答案；跳过练习不影响下一课所需功能，不能把必需逻辑藏在“留作练习”中 |

纯需求讨论单元不硬凑无关Go代码，但必须交付确定的需求结果、字段/错误示例或协议草稿；引入实际文件的单元必须提供可复制的完整文件。不能要求学生先自己猜对接口才给参考设计。

## 代码必须能连续积累

1. 新工程从空目录起步。使用稳定的目录与module命名，各课Proto、go_package、imports及启动路径相互一致。
2. 第N课的参考代码在第N−1课完成版本上可应用；替换整个文件时保留已有功能。目录或接口重构同时提供所有调用点的修改、生成和测试步骤。
3. 学生无须把旧MeshOps框架复制进新工程来补缺口。教师可以参考旧设计，但要在课程中给出新工程实际需要的完整实现。
4. 大文件可在讲解时拆成小段，但必须同时提供完整版本，明确“这里是解释片段”“这里是可直接保存的文件”。
5. 初期内存仓库、固定数据必须标注阶段用途。后续课程给出真正替换代码、接线与验证，最终业务不能残留未说明的占位路径。
6. 不让学生在RPC已被后课依赖时自行补函数体；所有必需任务都要有参考答案，不能以“类似前面”“自己接数据库”“其余略”跳过实现。
7. 课堂讨论和复制路径并行：学生可以先看解释直接复制，也可以先尝试再对照，两者到达相同的本课完成版本。

## 按什么证据判断参考代码可用

- 单课检查：从上一完成版本应用本课文件与命令，确认能构建、预期测试被发现，成功/错误路径符合讲义；导读课核对其引用的文件真实存在。
- 阶段检查：启动真实依赖和服务，按讲义操作看最终业务事实，不能用map示例或打印固定成功代替。
- 全程检查：在独立目录按给出的顺序从零复现，完成初始化、状态上报与查询/订阅、任务执行、故障恢复和最终验收。凡依赖教师机器的隐式步骤都要补进课程。
- 记录代码版本、命令、退出码和结果。环境不足、未运行、被跳过或用例未发现分别写清，不报告为已验证。
- “完整代码已编写”“复制流程已验证”“学生已理解”是三个状态，分别记录。代码能运行不直接代表理解，也不要求先证明独立实现才允许继续。
