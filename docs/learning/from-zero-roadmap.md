# 从零搭建教学路线

**学习正文从 [课程目录](from-zero/lessons/README.md) 进入。** 本页解释顺序和范围，不重复完整讲义。

目标是从空目录搭建一个持续演进的项目，能够说明功能、接口、文件与依赖为什么出现。全程使用 `example.com/meshops-course`，学习目录约定为 `D:\job\golang\projects\meshops-course-lab`。是否已创建和运行以用户反馈为准。

## 每阶段的成果

| 阶段 | 解决的问题 | 本阶段成果 |
| --- | --- | --- |
| Z00 | 输入实体 ID，应该返回什么 | 明确公共信息、可选组件、类型专属状态与缺失语义 |
| Z01 | 协议如何变为 Go 类型 | module、Proto、生成代码；理解目录与 go_package |
| Z02 | 怎样真正跨网络查询 | 第一个 go-zero Entity 服务与客户端，查询和错误处理 |
| Z03 | 状态怎样更新 | 临时写入与内存仓库，观察重启数据丢失，校验人员/无人机状态 |
| Z04 | 不同来源怎样安全接入 | 适配、来源绑定、身份校验、上报流与连续 ACK |
| Z05 | 怎样持久接收和投影 | Kafka 发布确认、消费位点、Redis 原子版本更新，拆出接入服务 |
| Z06 | 怎样应对断线和实时查看 | 六类来源、bbolt 队列、补传、按实体订阅与背压 |
| Z07 | 怎样可靠下发一次巡检 | Task/Dispatcher、MySQL 事务与 Outbox、执行去重、回报、取消、超时与死信 |
| Z08 | 怎样查历史 | 抽样、去重、清理、签名游标分页和完整操作端 |
| Z09 | 怎样证明可靠性 | 影子重建、故障恢复、性能与验收证据 |
| Z10 | 怎样检索任务并恢复索引 | MySQL → Canal → Kafka → ES、引导与重建、PIT 分页 |
| Z11 | 浏览器怎样调用后端 | HTTP/SSE 网关、会话、角色与 CSRF |
| Z12 | 怎样用页面操作真实数据 | Vue 控制台、实体地图、任务、搜索与模拟控制界面 |
| Z13 | 怎样部署完整成品 | Docker Compose、初始化与持久化、六类模拟器、运动与混合压测 |

Z04—Z13 再拆为 [28 个小步骤](from-zero/lessons/steps/README.md)。Z 是阶段，不预先强求课程数量等于 50。Z07 的最终装配文件较多，需要分组讲解，不能以一次编译成功代替理解。

## 每一步如何讲

1. 先给一个正常输入和一个失败输入，说明要解决的问题。
2. 讨论数据与规则，再设计接口；不让学生凭空猜字段。
3. 解释本步新增或替换的文件、依赖和服务边界。
4. 给完整文件答案、准确命令、工作目录和预期输出；逐段解释语法、调用、返回与错误。
5. 观察真实运行结果，再用必要测试固定关键规则。
6. 依据学生反馈补讲；AI 实现完成不表示学生已经掌握。

完整标准见 [参考代码交付标准](reference-code-standard.md)。自主尝试可选，跳过练习不应导致后续缺少必需业务代码。

## 范围与复杂度

先有需求再建目录，Z02 直接使用 go-zero；不要求先做另一套完整原生 gRPC 项目，也不以阅读根目录旧框架作为起点。日志、错误和测试随功能出现；Kafka、事务、幂等、恢复等能力逐步加入，早期内存示例不宣称可靠。

最终既有范围为六类实体、每实体一个权威来源、操作员选择执行实体、可信绑定选择执行方、一种 inspect。技术要求参照 [契约](../implementation/contracts.md) 和 [验收矩阵](../implementation/acceptance.md)。不包括路径规划、自动最优分配、真实设备控制与 AI agent。

任务搜索在 Z10 引入，网页与完整部署在 Z11—Z13 引入；早期阶段保留当时已学习的能力。百万实体容量验证未执行，不是现行课程必做项。完整参考代码及阶段证据见 [材料导航](from-zero/README.md)；学习进度见 [学习记录](../implementation/learning-progress.md)。
