# 实现检查：凭证、事务和搜索基础

本页解释搜索之前核对的工程机制，不要求先实现搜索。当前无注册和密码登录；操作员、服务、来源和执行方使用模拟环境生成的机器凭证。

## 凭证和网络边界

`scripts/env.ps1` 使用加密随机数生成器产生 32 字节随机凭证，存入被 Git 忽略的 `.local/secrets.json`。`Registry.Authenticate` 用 SHA256 查找对应身份，再做常量时间比较。这里处理的是高熵随机 token，不是人类密码，不能将这种方式照搬到注册密码存储。

当前凭证仍以明文存在本机文件和进程环境中，没有用户账号生命周期、集中密钥管理和生产证书体系。这是本机模拟范围，不声称已经是生产认证系统。

RPC 使用无 TLS 的本机连接。`LoadConfig` 校验监听地址和服务端点，`Dial` 在创建连接前再检查：必须是回环 IP 字面量与有效端口，客户端端口不能为 0。`0.0.0.0`、外部 IP、域名和 `dns:///...` 不能绕过限制。IPv4 `127.0.0.1` 与 IPv6 `::1` 可用；监听端允许端口 0，以便测试分配空闲端口。

因此把配置改为公网或局域网地址会明确失败。未来跨机器部署必须先设计 TLS/身份与秘密管理，不能只删除检查。MySQL/Kafka/Redis 的本地容器配置另按各自连接方式处理，本段限制针对应用 RPC。

## SQL、任务和版本

任务查询从认证上下文取得租户，SQL 把租户和参数放在占位符里。拼接的是固定字段与可选条件，不拼接用户输入。任务创建在同一 MySQL 事务内写任务、审计和 Outbox，幂等键由数据库唯一约束保护。

取消、回报和超时先通过 `SELECT ... FOR UPDATE` 锁住同一任务，再改变状态和递增版本。`persistChange` 的 UPDATE 没有再写版本条件，是因为调用者已经持有行锁；不能只看一条 UPDATE 就认定缺少并发控制。执行回报仍检查预期版本，终态不被迟到回报覆盖。

任务页游标使用 HMAC 签名，绑定租户、过滤条件和过期时间。搜索也必须沿用可信租户和游标范围，不能接受客户端随意指定租户或原始 ES 查询语句。

## 能用于搜索的文本

任务实例已有 `payload.note`（最多 256 UTF-8 字节）、`failure_reason` 和 `cancelled_reason`。`TaskDefinition.description` 是任务类型说明，不是每次任务的描述。成功结果由现有 inspect 契约严格校验，不能为了演示搜索随意增加字段。

第一版可对任务备注和失败/取消原因做关键词检索；状态、目标实体与时间作为过滤项。原始结果可以按契约展示，不将固定的 `outcome=ok` 包装成丰富报告全文检索。

## 重连计数也要对应实际行为

订阅断开后会等待退避。若观察时间在退避中结束，实际没有再次调用 Subscribe，就不应增加“重连次数”。计数现在在下一次调用开始时增加。新增测试用可控的客户端响应验证“只调用一次、重连数为零”，避免靠延长等待时间掩盖时序问题。
