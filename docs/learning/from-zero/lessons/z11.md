# Z11｜让浏览器通过 HTTP 调用已有 gRPC 服务

这课接在 Z10 后面。在同一个 `meshops-course-lab` 中增加浏览器接入层，保留已有 Entity、Task、Dispatcher、Search 的业务实现。完整创建与替换清单见 [Z11 完整文件答案](files/z11.md)。代码按文件整份复制，不把讲解片段当作另一个实现。

## 1. 先理解多出来的一跳

```text
浏览器 → HTTP/JSON → web-gateway → gRPC → Task / Entity / Dispatcher / Search
```

Task 查询 Entity 等内部调用仍使用 gRPC。浏览器接入层负责三个新问题：将 URL/JSON 转成 RPC；识别浏览器会话；把服务端订阅转换为浏览器可以读取的 SSE。

用户界面不直接拿到来源、执行方或管理员机器令牌。`ReportTaskStatus` 和 `ReportEntityStates` 没有 HTTP 路由。页面可以创建任务，但不能伪装执行方报告“已经成功”。

## 2. 声明 HTTP 映射

先创建完整答案中的 `proto/http.yaml`。其中一条映射是：

```yaml
- selector: meshops.task.v1.TaskService.CreateTask
  post: /api/v1/tasks
  body: '*'
```

逐项理解：

1. `selector` 是 Proto 包名、服务名和方法名；必须与已有 RPC 精确对应。
2. `post` 定义浏览器访问的 HTTP 方法和路径。
3. `body: '*'` 表示 JSON 请求体映射到 RPC 请求。请求中仍然没有可由用户填写的 tenant 身份。
4. `get: /api/v1/tasks/{task_id}` 中的花括号将 URL 段绑定到 `GetTaskRequest.task_id`。
5. 查询列表的 `page_size`、`page_token` 等字段来自 URL 查询参数。

你之前提到的 `option (google.api.http)` 是等价的声明方式：把规则写入 Proto。这里选择外部 YAML，保持早期课程的 Proto 文件和线协议不变；只管理浏览器允许访问的方法。

## 4. 按职责阅读手写代码

| 文件 | 阅读时要回答的问题 |
| --- | --- |
| `internal/web/server.go` | 配置如何进入 Server？为何要先做会话/权限检查，再交给生成路由？ |
| `internal/web/session.go` | 浏览器访问码如何换成随机 cookie？后端机器令牌为什么没有出现在响应里？ |
| `internal/web/stream.go` | 怎样持续接收 EntityUpdate？页面关闭或注销后谁负责取消 gRPC？ |
| `cmd/web-gateway/main.go` | 怎样装配四个 RPC 客户端？HTTP 服务如何启动和退出？ |

`New(Config)` 只装配处理器。`Handler()` 返回 `http.Handler`，`http.Server` 接收请求后才会执行里面的逻辑。这样测试可以在内存中调用处理器，也可以使用真实本机 HTTP/gRPC 连接验证转换。

认证的执行顺序是：

1. POST `/api/session` 只接受可信 Origin，检查角色与随机访问码。
2. 服务端生成随机 session ID 和 CSRF token，内存保存该会话对应的可信 actor、tenant 和 RPC token。
3. session ID 放进 `HttpOnly`、`SameSite=Strict` cookie；页面不通过 JavaScript 读取这个 cookie。
4. GET `/api/session` 返回角色、会话过期时间、CSRF token 和服务器时间；不返回 RPC token。
5. 后续写请求同时携带 cookie、可信 Origin 和 `X-CSRF-Token`，缺少条件会被拒绝。
6. 网关从可信会话生成 gRPC metadata，后端继续检查角色和对象归属。

这里的随机访问码是单机演示入口，不是用户注册/密码管理系统。服务端重启后内存会话失效，需要重新登录；磁盘中的访问码保留。后续如建设真实账号体系，应另设计用户、密码和角色管理，不能把随机机器 token 的 SHA-256 查找方式照搬成密码存储。

一个真实发现的细节：grpc-gateway 对 `Authorization` 有特殊处理，仅配置 header matcher 仍不足以阻止浏览器凭据参与上游调用。因此本实现先移除浏览器提供的 `Authorization`、`Grpc-Metadata-*`，再由会话映射生成可信 metadata。对应回归会发送伪造头，要求上游仍识别为登录的 operator。

## 5. 实体列表与实时更新

`GET /api/v1/entities` 从服务端可信注册表中取当前 tenant 的实体 ID、类型、执行器及能力，不返回全量注册表、原始来源凭证或其他租户。页面再用这些实体 ID 查询和订阅真实快照。

SSE 是一条保持打开的 HTTP 响应，消息例如：

```text
event: update
data: {"kind":"ENTITY_UPDATE_KIND_SNAPSHOT_END","syncId":"...","viewGeneration":"..."}
```

`stream.go` 使用已有 `Entity.Subscribe`。每条消息转换为 JSON 后写入浏览器；设置写入时限，避免慢页面无限占用连接。每会话最多两个订阅，全网关最多 32 个，每次 1—100 个授权实体。注销关闭会话的 done 通道，取消上游 gRPC；连接关闭和会话过期也会取消。

SSE 的连上网络不代表实体初始化完成。页面必须等待本次 `SNAPSHOT_END`，按 `sync_id` 和 `view_generation` 处理新同步，不能把旧版本当成跨实体断点。Z12 实现页面侧逻辑。

## 7. 启动时先后是什么

完整后端先按 Z10 启动；然后运行：

```powershell
./scripts/start-web.ps1
```

它启动 HTTP 网关，监听 `127.0.0.1:18090`。此时还没有网页，直接访问该根路径不会显示控制台。下一课启动 Vue 开发服务器后，从 `http://localhost:5173` 打开页面，由开发代理转发 `/api`。

访问码位于自己的 `.local/web-secrets.json`，由脚本首次生成。只把对应角色的浏览器访问码填写到登录表单，不能填写 `.local/secrets.json` 的服务凭据。网关日志在 `.local/logs/web.err.log`，停止它运行 `./scripts/stop-web.ps1`。

如果后端尚未启动，网关进程可以启动，但业务请求会返回不可用；`/livez` 只说明网关进程正在服务。404/405 查 URL 与方法；401 查会话/角色访问码；403 查 Origin、CSRF 和角色；503 查对应后端服务与依赖。

完成后应能解释：HTTP 转换代码解决了什么、为什么生成代码不能替代授权、页面为何不能回报任务执行成功，以及退出页面怎样取消订阅。

## 补充：演示控制接口

数量接口为 `PUT /api/v1/simulation/{source}/count`，JSON `{"count":5}`。先用指针字段区分缺少 count 与合法的 0，再校验整数范围、来源租户及候选容量。Redis 分开存储模式和数量，避免修改数量覆盖另一个请求的模式。`GET /api/v1/entities` 只列出启用的前 N 个 ID；授权仍校验完整注册表，减少数量不删除历史。参考 `TestSimulationCountBoundsAndActiveInventory` 验证边界、CSRF、隔离和非破坏性缩减。Z11 旧清单只有每类 1 个候选，完整的每类 5 个注册及生成器在 Z13 更新后生效。

本课完整代码包含 `internal/simulation` 和 `internal/web/simulation.go`。`GET /api/v1/simulation` 查询，`PUT /api/v1/simulation/{source}` 提交目标；202 不是执行成功。会话、CSRF 和来源租户校验沿用 Handler。目标持久化，实际状态由模拟器短期心跳提供。手工启用 `MESHOPS_SIMULATION_CONTROL=1` 才装配 Redis 控制；脚本已启用。此时旧模拟器还没有控制循环，显示无心跳是正常的，Z13 才完成模拟器装配。请逐行阅读完整文件答案，对照[三种模式说明](../../../simulation-map.md)。
