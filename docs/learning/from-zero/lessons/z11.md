# Z11｜让浏览器通过 HTTP 调用已有 gRPC 服务

这课接在 Z10 后面。在同一个 `meshops-course-lab` 中增加浏览器接入层和个人账号，保留已有 Entity、Task、Dispatcher、Search 的业务实现。完整创建与替换清单见 [Z11 完整文件答案](files/z11.md)。代码按文件整份复制，不把讲解片段当作另一个实现。账号、平台鉴权、服务装配、迁移 005、环境脚本与管理员 CLI 必须一起更新；只复制网关会造成 HTTP 已登录、内部 RPC 却不认识个人身份的错误。

## 1. 先理解多出来的一跳

```text
浏览器 → HTTP/JSON → web-gateway → gRPC → Task / Entity / Dispatcher / Search
```

Task 查询 Entity 等内部调用仍使用 gRPC。浏览器接入层负责三个新问题：将 URL/JSON 转成 RPC；识别浏览器会话；把服务端订阅转换为浏览器可以读取的 SSE。

用户界面不直接拿到来源、执行方或管理员机器令牌。`ReportTaskStatus` 和 `ReportEntityStates` 没有 HTTP 路由。页面可以创建任务，但不能伪装执行方报告“已经成功”。

## 2. 声明 HTTP 映射

先创建完整答案中的 `proto/http.yaml`。其中一条映射是：

```yaml
- selector: meshops.task.v1.TaskService.CreateTask
  post: /api/v1/tasks
  body: '*'
```

逐项理解：

1. `selector` 是 Proto 包名、服务名和方法名；必须与已有 RPC 精确对应。
2. `post` 定义浏览器访问的 HTTP 方法和路径。
3. `body: '*'` 表示 JSON 请求体映射到 RPC 请求。请求中仍然没有可由用户填写的 tenant 身份。
4. `get: /api/v1/tasks/{task_id}` 中的花括号将 URL 段绑定到 `GetTaskRequest.task_id`。
5. 查询列表的 `page_size`、`page_token` 等字段来自 URL 查询参数。

你之前提到的 `option (google.api.http)` 是等价的声明方式：把规则写入 Proto。这里选择外部 YAML，保持早期课程的 Proto 文件和线协议不变；只管理浏览器允许访问的方法。

## 4. 按职责阅读手写代码

| 文件 | 阅读时要回答的问题 |
| --- | --- |
| `internal/web/server.go` | 配置如何进入 Server？为何要先做会话/权限检查，再交给生成路由？ |
| `internal/web/session.go`、`accounts.go` | 用户名/密码如何换成 Cookie？哪些账号操作需要管理员或 CSRF？ |
| `internal/web/stream.go` | 怎样持续接收 EntityUpdate？页面关闭或注销后谁负责取消 gRPC？ |
| `cmd/web-gateway/main.go` | 怎样装配四个 RPC 客户端？HTTP 服务如何启动和退出？ |
| `migrations/005_accounts.sql` | 账号、会话和审计分别保存什么？唯一约束怎样限制用户名和初始管理员？ |
| `internal/accounts/password.go`、`store.go` | 密码怎样哈希与验证？禁用和改密怎样撤销旧会话？ |
| `internal/platform/auth.go`、`internal/app/run.go` | 原机器令牌与新增个人令牌怎样进入同一条可信鉴权链？ |
| `cmd/account-admin/main.go`、`scripts/account-admin.ps1` | 怎样在本机设置初始管理员，且不把密码写进命令参数？ |

`New(Config)` 只装配处理器。`Handler()` 返回 `http.Handler`，`http.Server` 接收请求后才会执行里面的逻辑。这样测试可以在内存中调用处理器，也可以使用真实本机 HTTP/gRPC 连接验证转换。

认证的执行顺序是：

1. POST `/api/session` 只接受可信 Origin 和 `{username,password}`；角色从账号记录读取，不能由浏览器选择。
2. 账号存储使用 Argon2id 验证密码，检查账号启用状态，并生成随机内部 RPC 令牌。数据库只保存该高熵令牌的 SHA-256 查找哈希、账号 ID、认证版本和到期时间。
3. 网关另外生成随机 session ID 与 CSRF token，在内存关联可信 actor、tenant、内部令牌。session ID 放进 `HttpOnly`、`SameSite=Strict` Cookie；页面不通过 JavaScript 读取这个 Cookie。
4. GET `/api/session` 返回角色、`username`、`displayName`、`mustChangePassword`、会话过期时间、CSRF token 和服务器时间；不返回密码哈希或内部 RPC 令牌。
5. 后续写请求同时携带 cookie、可信 Origin 和 `X-CSRF-Token`，缺少条件会被拒绝。
6. 网关从可信会话生成 gRPC metadata，后端查库验证个人令牌、认证版本、有效期和权限，再检查对象归属。任务审计因此记录具体账号 ID；来源、执行方和内部任务服务仍使用原机器凭证。

当前课程从本阶段开始启用个人账号。`env.ps1` 与 `web-env.ps1` 显式设置 `MESHOPS_ACCOUNT_AUTH=1`，必须同时重建并重启后端与网关。账号与密码哈希保存在 MySQL；网关重启后内存会话失效，需要重新登录。数据库错误会拒绝认证，不降级成默认用户。早期阶段的机器凭证练习仍保留，不能拿它替代最终页面的个人登录。

阅读 [密码实现](../../../../internal/accounts/password.go) 时，先找输入限制，再找生成随机盐和验证哈希串的路径：密码为 8—128 个 Unicode 字符、最多 512 个 UTF-8 字节，不裁剪；每次哈希使用独立 16 字节盐、64 MiB 内存、3 次迭代、并行度 1 和 32 字节输出。验证端限制可接受的哈希参数，登录端限制速率与并发计算数。不要将用于高熵随机令牌索引的 SHA-256 直接用于密码存储。

然后对照 [账号 HTTP 处理器](../../../../internal/web/accounts.go) 阅读以下接口；这些是手写账号路由，不由业务 Proto 映射生成：

| 接口 | 请求与成功结果 |
| --- | --- |
| `POST /api/session` | `{username,password}` → 当前会话 |
| `GET /api/session`、`DELETE /api/session` | 查询会话；注销返回 204 |
| `GET /api/accounts?limit=20&after=ID` | 管理员分页查询 → `{accounts,nextCursor}` |
| `POST /api/accounts` | 管理员提交 `{username,displayName,password}` → 新操作员，201 |
| `PATCH /api/accounts/{id}` | 管理员提交 `{enabled}` → 更新后的操作员 |
| `POST /api/accounts/{id}/reset-password` | 管理员提交 `{password}` → 204 |
| `POST /api/account/password` | 本人提交 `{currentPassword,newPassword}` → 204，随后重新登录 |

账号对象仅包含 ID、用户名、显示名称、角色、启用/强制改密状态及创建/更新时间。创建操作员或重置其密码后必须先改密；此时后端仅允许查询/退出会话和本人改密，其余业务请求拒绝。管理员不能通过操作员管理接口创建另一个管理员、停用初始管理员或修改角色。禁用、改密、重置和注销撤销对应凭证；当前网关也会取消该用户的 SSE。完整生命周期与恢复操作见 [个人账号手册](../../../operations/accounts.md)。

一个真实发现的细节：grpc-gateway 对 `Authorization` 有特殊处理，仅配置 header matcher 仍不足以阻止浏览器凭据参与上游调用。因此本实现先移除浏览器提供的 `Authorization`、`Grpc-Metadata-*`，再由会话映射生成可信 metadata。对应回归会发送伪造头，要求上游仍识别为登录的 operator。

## 5. 实体列表与实时更新

`GET /api/v1/entities` 从服务端可信注册表中取当前 tenant 的实体 ID、类型、执行器及能力，不返回全量注册表、原始来源凭证或其他租户。页面再用这些实体 ID 查询和订阅真实快照。

SSE 是一条保持打开的 HTTP 响应，消息例如：

```text
event: update
data: {"kind":"ENTITY_UPDATE_KIND_SNAPSHOT_END","syncId":"...","viewGeneration":"..."}
```

`stream.go` 使用已有 `Entity.Subscribe`。每条消息转换为 JSON 后写入浏览器；设置写入时限，避免慢页面无限占用连接。每会话最多两个订阅，全网关最多 32 个，每次 1—100 个授权实体。注销关闭会话的 done 通道，取消上游 gRPC；连接关闭和会话过期也会取消。

SSE 的连上网络不代表实体初始化完成。页面必须等待本次 `SNAPSHOT_END`，按 `sync_id` 和 `view_generation` 处理新同步，不能把旧版本当成跨实体断点。Z12 实现页面侧逻辑。

## 6. 停旧进程、迁移和重建

在 PowerShell 7 中进入自己的学习目录。若 Z10 后端仍在运行，必须先停止，防止旧进程占用端口或 Windows 锁住待替换的 `.exe`。参考目录也在运行课程后端时，先回到参考目录用它自己的停止脚本处理，不能同时用不同目录的凭证 seed 同一数据库。

```powershell
Set-Location 'D:\job\golang\projects\meshops-course-lab'
if (Test-Path './scripts/stop-web.ps1') { ./scripts/stop-web.ps1 }
./scripts/stop.ps1
docker compose -f docker-compose.yml -f compose.search.yml --profile search stop canal
if ($LASTEXITCODE -ne 0) { throw 'stop Canal failed' }
```

停止写入和 Canal 后，按 [Z11 完整文件答案](files/z11.md) 完整复制/替换文件，再执行：

```powershell
Test-Path './migrations/005_accounts.sql'
Test-Path './cmd/account-admin/main.go'
./scripts/initialize.ps1
./scripts/initialize-search.ps1
go test ./internal/accounts ./internal/web ./internal/platform ./cmd/account-admin -count=1 -v
if ($LASTEXITCODE -ne 0) { throw 'account and gateway tests failed' }
```

两个 `Test-Path` 应为 `True`。`initialize.ps1` 会复用本目录 `.local/secrets.json`、启动课程中间件、调用 `build.ps1` 重建包括 `web-gateway.exe` 与 `account-admin.exe` 在内的程序，再执行实际命令 `./bin/opctl.exe seed --manifest configs/simulation.yaml --token-env MESHOPS_ADMIN_TOKEN`。`seed` 内部先运行未应用的 SQL 迁移，再检查绑定并准备 Kafka；本工程没有独立的 `opctl migrate` 子命令。迁移 005 创建 `accounts`、`account_sessions`、`account_audit`，不插入默认密码，也不删除任务与历史。不要重新生成机器凭证、删除课程数据库或使用 Docker Reset 来“完成迁移”。

`initialize-search.ps1` 随后检查已有搜索引导并恢复 Canal。已有标记时只准备其所需凭据；搜索事实或位点损坏要按搜索恢复流程处理，不能手写完成标记。此前已完整初始化的目录也需要本次重建与迁移，不能仅启动旧 Z10 二进制。

普通测试应包含 `TestPasswordPolicyAndArgonBounds`、`TestAccountMustChangeAndRevocation`、`TestAccountRejectsRoleSpoofAndUsesPersonalToken`。它们不代替真实数据库与 HTTP/RPC/SSE 撤销测试；需要完整依赖验收时执行 `./scripts/test.ps1 -Integration`，保留结果并确认必需用例实际执行，不将跳过算作通过。

## 7. 设置管理员后启动网关

迁移成功后，在同一学习目录执行：

```powershell
./scripts/account-admin.ps1 -Mode Local -Action Status
./scripts/account-admin.ps1 -Mode Local -Action Setup -Username admin
./scripts/account-admin.ps1 -Mode Local -Action Status
./scripts/start.ps1 -Simulators -Search
./scripts/start-web.ps1
```

第一次 Setup 提示两次安全输入密码，密码由你设置；不要在命令参数或教程文件中填写密码。脚本经标准输入把密码交给 Go CLI，输出只说明账号已就绪。最后一次 Status 应显示 `initialized: true` 和管理员用户名。重复 Setup 只检查已有管理员，**不会改密**。忘记密码时由本机管理者执行 `./scripts/account-admin.ps1 -Mode Local -Action Reset -Username admin`，这是显式改密恢复，会撤销旧会话；不需要清库。`-Mode Local` 使用课程数据库，省略时默认 Docker，两者不能混用。

网关监听 `127.0.0.1:18090`。此时还没有网页，直接访问根路径不会显示控制台。下一课启动 Vue 开发服务器后，从 `http://localhost:5173` 打开页面，由开发代理转发 `/api`，输入上面设置的用户名和密码。`.local/secrets.json` 仍用于机器服务，不是网页登录凭证。网关日志在 `.local/logs/web.err.log`，停止它运行 `./scripts/stop-web.ps1`。

`/livez` 只说明网关进程正在服务。404/405 查 URL 与方法；401 查账号密码或重新登录；403 查强制改密、Origin、CSRF 和角色；429 等待限流/并发计算恢复，避免连续重试；503 查数据库及对应后端服务。页面能登录不代表全部 RPC 已就绪。

完成后应能解释：HTTP 转换代码解决了什么、为什么生成代码不能替代授权、密码哈希与随机令牌哈希为何不同、个人身份怎样进入任务审计，以及改密和退出怎样取消订阅。

## 补充：演示控制接口

数量接口为 `PUT /api/v1/simulation/{source}/count`，JSON `{"count":5}`。先用指针字段区分缺少 count 与合法的 0，再校验整数范围、来源租户及候选容量。Redis 分开存储模式和数量，避免修改数量覆盖另一个请求的模式。`GET /api/v1/entities` 只列出启用的前 N 个 ID；授权仍校验完整注册表，减少数量不删除历史。参考 `TestSimulationCountBoundsAndActiveInventory` 验证边界、CSRF、隔离和非破坏性缩减。Z11 旧清单只有每类 1 个候选，完整的每类 5 个注册及生成器在 Z13 更新后生效。

本课完整代码包含 `internal/simulation` 和 `internal/web/simulation.go`。`GET /api/v1/simulation` 查询，`PUT /api/v1/simulation/{source}` 提交目标；202 不是执行成功。会话、CSRF 和来源租户校验沿用 Handler。目标持久化，实际状态由模拟器短期心跳提供。手工启用 `MESHOPS_SIMULATION_CONTROL=1` 才装配 Redis 控制；脚本已启用。此时旧模拟器还没有控制循环，显示无心跳是正常的，Z13 才完成模拟器装配。请逐行阅读完整文件答案，对照[三种模式说明](../../../simulation-map.md)。
