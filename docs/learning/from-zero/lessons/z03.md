# Z03｜临时写入状态，用内存仓库查询人员和无人机

Z02 只查固定的一名人员。本课提出新需求：“客户端写入一个对象的位置，再查询它；再次写入相同编号时，用新快照替换旧快照。”

因此才引入写入接口、map 和锁。**PutSnapshot 是本课临时教学接口，后续正式接入 Ingest 会替换它；它的成功只代表本进程内存已更新，不代表落盘、消息确认或持久化成功。**

<!-- generated-code:end -->

读写使用同一个 `entity_id`。写请求需要完整 snapshot，响应只回编号。我们故意没有把字段叫 durable、committed 或 persisted，因为当前没有任何持久介质。

同编号第二次 Put 是整体替换，不是部分补丁。因此第二次未传电量，会把前一次电量移除成未知。这里也没有来源版本排序：并发写同一编号时，以最后取得写锁并完成赋值的请求为当前值，不能根据客户端时间推断“最新”。正式事件接入在后续处理这一问题。

## 3. 内存仓库：map 为什么不能直接暴露

新建 `internal/repository/memory.go`：

<!-- source:internal/repository/memory.go -->
<!-- generated-code:start -->
```go
package repository

import (
	"errors"
	"math"
	"regexp"
	"sync"

	commonv1 "example.com/meshops-course/gen/common/v1"
	"google.golang.org/protobuf/proto"
)

var idPattern = regexp.MustCompile(`^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`)

func ValidID(id string) bool { return idPattern.MatchString(id) }

// Memory owns its map and all messages stored inside it.
type Memory struct {
	mu   sync.RWMutex
	rows map[string]*commonv1.EntitySnapshot
}

func New() *Memory {
	return &Memory{rows: make(map[string]*commonv1.EntitySnapshot)}
}

func finite(v float64) bool { return !math.IsNaN(v) && !math.IsInf(v, 0) }

func Validate(id string, snapshot *commonv1.EntitySnapshot) error {
	if !ValidID(id) {
		return errors.New("entity_id must be 1..64 ASCII letters, digits, dot, underscore or hyphen; first character must be alphanumeric")
	}
	if snapshot == nil {
		return errors.New("snapshot is required")
	}
	if snapshot.EntityType != "person" && snapshot.EntityType != "drone" {
		return errors.New("entity_type must be person or drone")
	}
	loc := snapshot.Location
	if loc == nil {
		return errors.New("location is required")
	}
	if !finite(loc.Latitude) || loc.Latitude < -90 || loc.Latitude > 90 {
		return errors.New("latitude must be finite and within -90..90")
	}
	if !finite(loc.Longitude) || loc.Longitude < -180 || loc.Longitude > 180 {
		return errors.New("longitude must be finite and within -180..180")
	}
	if power := snapshot.Power; power != nil && power.BatteryPercent != nil {
		value := *power.BatteryPercent
		if !finite(value) || value < 0 || value > 100 {
			return errors.New("battery_percent must be finite and within 0..100")
		}
	}
	return nil
}

func (m *Memory) Put(id string, snapshot *commonv1.EntitySnapshot) error {
	if err := Validate(id, snapshot); err != nil {
		return err
	}
	// Clone prevents subsequent caller edits from changing our stored row.
	owned := proto.Clone(snapshot).(*commonv1.EntitySnapshot)
	m.mu.Lock()
	defer m.mu.Unlock()
	m.rows[id] = owned
	return nil
}

func (m *Memory) Get(id string) (*commonv1.EntitySnapshot, bool) {
	m.mu.RLock()
	defer m.mu.RUnlock()
	row, found := m.rows[id]
	if !found {
		return nil, false
	}
	// Readers receive their own deep copy, including nested optional fields.
	return proto.Clone(row).(*commonv1.EntitySnapshot), true
}
```
<!-- generated-code:end -->

先拆开类型：

```go
type Memory struct {
    mu   sync.RWMutex
    rows map[string]*commonv1.EntitySnapshot
}
```

`map[string]*EntitySnapshot` 表示“字符串编号 → 快照指针”。`mu` 与 `rows` 小写开头，不导出给其他包。外部只能调用方法，不能直接随意写 map。

`New()` 返回新仓库指针。`make(map[...])` 分配可写 map；只声明一个 nil map 然后赋值会 panic。调用一次 New 就得到一个新的空仓库，程序重启也会重新调用 New，这正是数据会丢失的原因。

### Validate：在写入前拒绝不合格数据

`ValidID` 用预编译正则要求编号为 1～64 个 ASCII 字母、数字、点、下划线或连字符，首字符必须为字母或数字。Z02 只检查空白；现在有写入口，读写共享更明确的编号约束。

`Validate(id string, snapshot *EntitySnapshot) error` 不修改数据；成功返回 nil，失败返回一个可读错误。检查顺序是编号 → 快照非空 → 类型 → 位置存在 → 经纬度范围及有限性 → 可选电量范围及有限性。

`math.IsNaN` 与 `math.IsInf` 很必要：NaN 与数字比较时通常都不成立，仅写 `x < 0 || x > 100` 会漏掉 NaN。经纬度分别允许 -90～90、-180～180，电量允许 0～100，端点都有效。

缺失 Power 或缺失 BatteryPercent 都允许，表示未知。明确 0 也允许。类型仅接受本阶段教到的 person 与 drone，其他类型返回错误；后续扩展类型时需要同时更新协议含义、校验和测试。

### Put：校验、深拷贝、加锁、赋值

`Put(id, snapshot) error` 先验证，所以无效写入不会覆盖已有的好数据。

`proto.Clone(snapshot)` 深拷贝消息及嵌套对象，返回类型是通用的 proto.Message。`.(*commonv1.EntitySnapshot)` 是类型断言：告诉编译器我们知道克隆出来仍是 EntitySnapshot。因为此前已经拒绝 nil 且输入类型固定，这个断言与函数契约一致。

为什么不能只写 `m.rows[id] = snapshot`？因为调用者以后可能修改自己持有的指针。仓库会无声变化，甚至绕开锁产生并发问题。克隆以后仓库拥有独立对象。调用者仍应遵守一条普通 Go 所有权规则：**不要在 Put 正在读取/克隆输入时，由另一个 goroutine 同时修改同一输入对象。** RPC 解码得到的单次请求天然独立，本课并发测试也每次创建独立消息。

`Lock()` 取得独占写锁。`defer Unlock()` 确保函数结束释放。`m.rows[id] = owned` 对新编号是新增，对已有编号是覆盖。锁保护的是一次 map 操作和该操作可见性，不是磁盘事务。

### Get：读锁和第二次深拷贝

`Get(id) (*EntitySnapshot, bool)` 返回快照与是否存在。`row, found := m.rows[id]` 是 Go 的 map 双返回值写法；不能只看快照字段的零值猜测是否找到。

`RLock()` 允许多个读者同时持有读锁，但与写锁互斥。找到后再次 Clone，是为了让调用者修改返回值时也不会影响仓库。**入库时拷贝防止外部改输入，出库时拷贝防止外部改输出，两次各有作用。**

## 4. 服务层：只负责 RPC 语义与错误转换

完整替换 `internal/service/entity.go`：

<!-- source:internal/service/entity.go -->
<!-- generated-code:start -->
```go
package service

import (
	"context"

	entityv1 "example.com/meshops-course/gen/entity/v1"
	"example.com/meshops-course/internal/repository"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type EntityServer struct {
	entityv1.UnimplementedEntityServiceServer
	repo *repository.Memory
}

func New() *EntityServer { return &EntityServer{repo: repository.New()} }

func (s *EntityServer) GetSnapshot(ctx context.Context, req *entityv1.GetSnapshotRequest) (*entityv1.GetSnapshotResponse, error) {
	if err := ctx.Err(); err != nil {
		return nil, status.FromContextError(err).Err()
	}
	id := req.GetEntityId()
	if !repository.ValidID(id) {
		return nil, status.Error(codes.InvalidArgument, "invalid entity_id")
	}
	row, found := s.repo.Get(id)
	return &entityv1.GetSnapshotResponse{EntityId: id, Snapshot: row, Found: found}, nil
}

// PutSnapshot is a teaching-only RPC; final ingestion replaces it.
func (s *EntityServer) PutSnapshot(ctx context.Context, req *entityv1.PutSnapshotRequest) (*entityv1.PutSnapshotResponse, error) {
	if err := ctx.Err(); err != nil {
		return nil, status.FromContextError(err).Err()
	}
	if err := s.repo.Put(req.GetEntityId(), req.GetSnapshot()); err != nil {
		return nil, status.Error(codes.InvalidArgument, err.Error())
	}
	// This acknowledges an in-process memory write only.
	return &entityv1.PutSnapshotResponse{EntityId: req.GetEntityId()}, nil
}
```
<!-- generated-code:end -->

New 创建一次仓库，并存入服务器结构体，所以同一服务生命周期内的请求共享状态。如果你把 `repository.New()` 写进每次 GetSnapshot 中，写入后查询仍是空，这会破坏需求。

GetSnapshot 先检查上下文及编号，再取仓库结果，原样构造 Found 与 Snapshot。PutSnapshot 先检查上下文，再调用仓库；校验失败用 `status.Error(codes.InvalidArgument, err.Error())` 转成客户端能识别的 RPC 错误码。

成功响应的注释和客户端输出都明确写着 memory-only。客户端如果超时，并不能仅凭超时断言服务器完全没写入：请求与响应之间可能发生网络问题。当前同编号整体覆盖的教学接口没有正式事件幂等语义；这些由后续 Ingest 设计承担。

Z02 的固定 `person-001` 已删除。本课**服务刚启动时，查询任意合法编号都应 found=false**。

## 5. 写入客户端：为什么 battery 参数用字符串

新建 `cmd/put/main.go`：

<!-- source:cmd/put/main.go -->
<!-- generated-code:start -->
```go
package main

import (
	"context"
	"flag"
	"fmt"
	"os"
	"strconv"
	"time"

	commonv1 "example.com/meshops-course/gen/common/v1"
	entityv1 "example.com/meshops-course/gen/entity/v1"
	"google.golang.org/grpc"
	"google.golang.org/grpc/credentials/insecure"
	"google.golang.org/grpc/status"
)

func run() error {
	addr := flag.String("addr", "127.0.0.1:50163", "server address")
	id := flag.String("id", "person-001", "entity ID")
	kind := flag.String("type", "person", "person or drone")
	lat := flag.Float64("lat", 31.2304, "latitude in degrees")
	lon := flag.Float64("lon", 121.4737, "longitude in degrees")
	battery := flag.String("battery", "", "battery percent; omitted means unknown")
	flag.Parse()
	row := &commonv1.EntitySnapshot{EntityType: *kind, Location: &commonv1.Location{Latitude: *lat, Longitude: *lon}}
	if *battery != "" {
		value, err := strconv.ParseFloat(*battery, 64)
		if err != nil {
			return fmt.Errorf("battery must be a number: %w", err)
		}
		row.Power = &commonv1.PowerState{BatteryPercent: &value}
	}
	conn, err := grpc.NewClient(*addr, grpc.WithTransportCredentials(insecure.NewCredentials()))
	if err != nil {
		return err
	}
	defer conn.Close()
	client := entityv1.NewEntityServiceClient(conn)
	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
	defer cancel()
	reply, err := client.PutSnapshot(ctx, &entityv1.PutSnapshotRequest{EntityId: *id, Snapshot: row})
	if err != nil {
		return err
	}
	fmt.Printf("id=%s stored=memory-only\n", reply.GetEntityId())
	return nil
}

func main() {
	if err := run(); err != nil {
		fmt.Fprintf(os.Stderr, "put failed: code=%s message=%s\n", status.Code(err), status.Convert(err).Message())
		os.Exit(1)
	}
}
```
<!-- generated-code:end -->

地址、编号和类型用 `flag.String`，经纬度用 `flag.Float64`。`battery` 特意用字符串并默认空：

- 没有 `-battery`：字符串为空，不创建 Power。
- `-battery 0`：字符串是 `"0"`，ParseFloat 得到 0，并创建带非 nil BatteryPercent 的 Power。
- `-battery abc`：ParseFloat 本地失败，客户端尚未发出 RPC。
- `-battery 101`：成功解析成数字，但服务器 Validate 返回 InvalidArgument。

如果使用默认值为 0 的 Float64 又不检查参数是否提供，就会混淆未上报和 0%。`&value` 保存明确数值的地址，Go 会确保该变量的生命周期足够长，不会因 if 代码块结束就变成悬空指针。

连接、三秒超时、defer 清理、错误输出与 Z02 query 一致。发送的是完整 PutSnapshotRequest；成功打印 `stored=memory-only`。

|---|---|---|
| TestPutGetAndClone | 写入后改输入，再改 Get 返回值，重新读取 | 两个方向没有指针别名泄漏；0 与未知可区分 |
| TestInvalidInputsDoNotOverwrite | 空/非法编号、缺失快照/位置、非法类型、越界、NaN/Inf | 非法数据返回错误且不覆盖原始好行 |
| TestConcurrentReadersAndWriters | 16 个 goroutine，每个执行 100 次独立写读 | 并发 map 操作有读写锁保护，读到有效快照 |
| TestNewRepositoryLosesPreviousProcessState | 建第二个仓库再读 | New 的状态是独立空内存 |
| TestRPCSemantics | 直接调服务方法，验证写读更新/非法/取消 | 仓库结果被正确转换成 RPC 响应及错误 |
| smoke.ps1 | 编译并启动真正服务、写人/无人机、更新、拒绝、停进程再启动 | 跨网络调用和真实进程重启后的丢失 |

`sync.WaitGroup` 用 Add 登记工作数，每个 goroutine 结束时 Done，主测试 Wait 等待所有工作结束。`go func(worker int) {...}(i)` 把当前 i 作为参数交给并发函数。`t.Run` 是表驱动测试的子案例名；失败能直接定位到具体非法输入。

执行：

```powershell
go test ./... -count=1
powershell -NoProfile -ExecutionPolicy Bypass -File .\smoke.ps1
if ($LASTEXITCODE -ne 0) { throw 'smoke failed' }
```

`-count=1` 禁用测试结果缓存，让本次重新执行。当前实测仓库和服务测试为 ok；smoke 完成时打印：

```text
invalid latitude rejected: InvalidArgument
id=drone-001 found=true type=drone lat=32.0000 lon=121.4737 power=80.0%
id=person-001 found=false
id=drone-001 found=false
PASS: z03 real gRPC write/query/update/rejection/restart loss
```

这是 smoke 后半段；前半段还会打印写入及读取结果。脚本使用系统分配的临时端口，产物放 `.local/`，并在 finally 里停止自己创建的服务，不要求先关闭手工实验的 50163 服务。若启动失败，检查 `.local/entity.err.log`。

并发功能测试不等同于运行 race detector。Windows 的 `go test -race` 还需要 CGO 和兼容的 C 编译器；本课的必需验收是上述已跑通命令，不把未执行的 race 检查写成通过。

## 10. 常见错误与过渡

| 现象 | 原因与修复 |
|---|---|
| PutSnapshot 未定义或接口不匹配 | 修改 Proto 后忘记生成，重新运行 generate.ps1 |
| 写入成功但查询为空 | 两个命令是否连同一端口？是否误启动 Z02？仓库是否被每次请求重新 New？ |
| 更新电量后又变 unknown | 新 Put 是整份快照替换；不传 battery 就不保留旧字段 |
| 并发 map panic | 检查 Get/Put 是否始终经过同一个 Memory 实例的锁 |
| 重启后全没了 | 当前设计就是内存生命周期，没有持久化 |
| 测试只有 [no test files] | 检查 internal/repository 和 internal/service 下的 *_test.go 是否完整复制 |

现在已经亲自完成“定义协议 → 生成类型 → 启动 go-zero → 查询 → 写入 → 更新 → 失败 → 重启”这一条最小链路。下一课 [Z04](z04.md) 以这个现象为起点，逐步替换临时 PutSnapshot；进入完整参考工程时不能把本课 Proto 覆盖过去，正式接口及事件字段会按后续课文添加。
