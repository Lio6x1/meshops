# Z04｜把不同来源转换成统一实体事件

Z03 的客户端直接写入平台快照。现在模拟真实接入：人员系统用 `employee_id`、小数经纬度；无人机系统用 `aircraft_id`、放大一千万倍的整数经纬度。我们自己生成这些原始数据，也自己完成转换，不假设上游已经统一。

本阶段已经细化为四个各自可编译、验证范围明确的步骤。亲手搭建从 [小步骤操作说明](steps/README.md) 和 [Z04-01文件清单](steps/z04-01.md) 开始；本页提供配套代码解释。前面先编译协议、测试转换和确认规则，第四步才启动服务。全部阶段结束文件另见 [Z04 文件答案](files/z04.md)。你仍在 `D:\job\golang\projects\meshops-course-lab` 工作，先停止 Z03 服务。

## Z04-01：先定义一条事件，不急着写服务

打开答案中的 `proto/common/v1/entity.proto` 和 `proto/ingest/v1/ingest.proto`。先写协议，再运行 `scripts/generate.ps1`，或者复制清单中的全部生成文件。公共实体协议引用任务目录消息，因此本阶段也提供被引用的任务 Proto；定义存在不代表任务服务已经实现。

区分两个东西：snapshot 是“这架无人机现在的状态”；event 是“哪个可信来源，在什么时间，以什么版本报告了这份状态”。有了事件外层，重放、去重、归属检查才有依据。

| 字段 | 示例及用途 |
| --- | --- |
| tenant_id、entity_id | 租户和统一实体编号；不同租户可以使用相同编号 |
| source_id、source_generation | 当前权威来源及其配置代次；来源不能自行抢占实体 |
| entity_version | 同一实体的递增状态版本；用于拒绝旧状态 |
| event_id | 一条业务事件的身份；网络重发必须保留 |
| occurred_at | 来源声称的发生时间，用于新鲜度和历史 |
| received_at | Ingest 本次接收时间，由服务端覆盖 |
| operation | UPSERT 带完整快照，DELETE 不带快照 |
| expires_at | 状态的有效期，不等于应该删除版本记录的时间 |

队列 sequence 又是另一个编号：它标记网关队列中的位置，一个队列可包含多个实体。不能用无人机 version=8 推断网关已经确认前八条数据。

统一实体并不是强迫每类实体拥有一样的字段。共同外层承载身份、版本和位置等组件，人员有 PersonState，无人机有 PowerState。正式校验禁止给人员塞无人机电量组件。Z03 的宽松内存示例到这里收紧为约定模型。

## Z04-02：写适配器，把单位和身份整理正确

依次创建完整答案中的 `internal/platform/types.go`、配置与 registry 实现，以及 `internal/state/adapters.go`、`validation.go`。来源与绑定清单位于 `configs/simulation.yaml`；`configs/server.yaml` 的 `MeshOps.Manifest` 指向它，`internal/platform/registry.go` 负责读取并校验。

适配器真实代码片段如下，只用于解释；复制时使用答案里的完整 `adapters.go`：

```go
rawID, err := field[string](m, ids[source.Adapter], true)
if err != nil {
    return nil, err
}
entity, ok := source.Entities[rawID]
if !ok {
    return nil, fmt.Errorf("unregistered raw entity ID")
}
```

1. `m` 保存已经严格解析的 JSON 字段。`field[string]` 是泛型函数调用，要求目标字段是字符串；最后的 `true` 表示必填。
2. `ids[source.Adapter]` 根据适配器选择字段名：人员取 employee_id，无人机取 aircraft_id。
3. `source.Entities` 是配置中的原始编号到平台编号映射。它不会把任意陌生编号自动注册进平台。
4. `ok` 为 false 立即失败，避免设备通过改一个编号去更新别人的实体。

无人机的位置转换调用为：

```go
snap.Location, err = location(m, "lat_e7", "lon_e7", "altitude_cm", 1e7, 100)
```

前两个数除以一千万得到角度，海拔除以一百得到米。例如纬度312300000得到31.23度。转换函数还检查纬度、经度必须成对出现，拒绝 NaN、无穷大和越界坐标。不要仅靠 Go 的 float64 能存下一个值就认为该位置有效。

`decodeObject` 拒绝未知键和重复键；`field` 区分字段缺失、null 和明确的零。电量0是有效上报，不能写成 `if battery == 0 { 未上报 }`。`ordered` 对技能等集合排序去重，避免同样的内容仅因顺序不同产生冲突。

`GenerateRaw` 读取 fixture 后刷新编号、版本与时间，便于反复实验。`Normalize` 才负责把原始格式转成统一事件。两者分开：以后接入真实设备时，替换数据产生方式，仍可以使用相同适配逻辑。

## Z04-03：验证调用者，再验证他能更新哪个实体

阅读完整的 `internal/platform/auth.go`。服务拦截器从 metadata 读取 Bearer token，经 registry 认证后构造 Principal，放到 context。业务函数使用 `platform.Identity(ctx)` 获取它，不能相信请求体里自称的租户。

普通 RPC 使用 registry 的 `Unary()` 拦截器；Ingest 是双向流，使用 `Stream()`。流包装器重写 Context，让后续 `stream.Context()` 能取到身份。只给普通 RPC 加鉴权会漏掉长连接，这是两种拦截器都存在的原因。

接下来读 `Validate`：先检查事件格式，再检查 registry 中实体绑定的 source ID、source generation 和实体类型。最后根据可信配置填充 task catalog。无人机自报 supported_tasks 只接受格式检查，不能因此获得执行任务的权限。

本阶段仍使用本地明文 gRPC 连接，这是给本机模拟环境的配置。Bearer 是调用身份，不是加密协议；不要在讲解中把两者说成同一件事。

## Z04-04：接收批次、确认连续前缀，再查询

现在创建 `internal/state/ingest.go`、`memory.go`、`cmd/course/main.go` 以及清单中的脚本、配置、fixture 和测试。旧 `PutSnapshot`、旧服务包与 main 的删除清单也必须处理，否则旧代码还会引用已变化的协议。

`NewIngest` 接收一个 Publisher 接口。Z04 传入 MemoryEntity，Z05 换成 Kafka。下面是完整接口：

```go
type Publisher interface {
    Publish(context.Context, string, string, []byte) error
}
```

1. context 控制取消及超时；两个 string 是 topic 和 key；字节切片是序列化事件。
2. 接口不要求继承或显式声明 implements。MemoryEntity 有相同方法签名，就能传进去。
3. 接口统一了调用方式，但不会统一可靠性：内存 Publish 成功仍会在重启时丢失。

`ReportEntityStates` 持续 Recv。先检查来源只能有一个活动流、批次大小、epoch 和连续 sequence；随后校验并编码整批，再开始发布。这保证“第二条格式非法”不会导致第一条已经写入。

发布失败则是另一种情况，可能发生部分成功。例如 sequence 21成功、22失败、23成功，ACK只能确认到21。源码用 `prefix` 在首个失败后阻止确认继续前进。重连后重发22、23，所以消费者必须能去重。不能把确认值直接写成最大的成功编号23。

MemoryEntity 使用锁保护读改写，按实体版本比较：旧版本忽略；同版本、同 event ID、同内容视为重复；同版本不同内容拒绝；更新版本替换。删除仍保留事件版本，查询返回 found=false。收到旧 UPSERT 时不能把已经删除的实体复活。

终端一持续运行。终端二进入同一目录并执行 `. ./scripts/env.ps1`，然后：

```powershell
./bin/course.exe report --endpoint 127.0.0.1:25151 --source personnel_sim --id person-001 --version 1
./bin/course.exe get --endpoint 127.0.0.1:25151 --id person-001
./bin/course.exe report --endpoint 127.0.0.1:25151 --source drone_sim --id drone-001 --version 1
./bin/course.exe get --endpoint 127.0.0.1:25151 --id drone-001
```

预期两次查询 found=true，类型分别为 person、drone，version=1。继续上报应改为 version=2；再次运行 version=1 会生成新的事件内容，并不是合法的原事件重放。

重点对照测试 `TestTwoAdapters`、`TestWholeBatchAndPrefixACK`、`TestMemoryVersionAndTenantRules`：它们分别验证单位/格式、确认边界、版本/租户。读测试时先找输入，再找断言，不要只看 PASS。

| 现象 | 原因与操作 |
| --- | --- |
| Connection refused | 服务未启动或还在用 Z03 端口；检查终端一 |
| PermissionDenied | 凭证或实体来源绑定不匹配；对照本阶段配置，不改鉴权代码绕过 |
| source already connected | 相同来源已有活动流；先停止旧进程 |
| 同版本冲突 | 生成了新内容却沿用了版本；递增版本，真实重试则重发原事件 |
| 重启后查不到 | 当前存储仍是内存，是 Z05 要解决的问题 |
