# Z08｜抽样保存实体历史并稳定分页

Z07已经能回答“现在怎样”“任务执行到哪了”。本阶段增加实体历史样本，按 [Z08-01](steps/z08-01.md)、[Z08-02](steps/z08-02.md)两个文件步骤编译和验证，接线与解释见 [小步骤说明](steps/remaining.md)。完整阶段答案另见 [Z08文件](files/z08.md)。保留配置、凭证、队列和数据库；Entity构造增加MySQL连接，必须同步调用者。下文三段是讲解主题，不是另外三个文件版本。

## 采样规则：明确保存样本，而不是每一帧

阅读 `internal/state/history.go` 的 `sampleReason`，完整文件见答案。它比较当前事件与上一次已保存样本，优先检查状态变化，再检查位置、速度或航向变化，最后检查采样周期。

```go
if a.Status != b.Status {
    return "state_change"
}
if (a.Location == nil) != (b.Location == nil) || a.Location != nil && b.Location != nil && meters(a.Location, b.Location) >= 50 {
    return "position"
}
```

1. 首个样本返回periodic，后续先看状态是否不同。
2. 位置从未知变已知也算位置变化；两边都存在才计算距离，避免解引用nil。
3. 大于等于50米触发位置样本。这里只是采样规则，不是路径规划算法。
4. 速度变化比例、航向最小夹角和周期的规则紧随其后。多个条件同时满足时，返回最先命中的原因，不会为同一事件插入四行。

这不是全量轨迹归档，也不是随时能精确恢复每毫秒状态的事件库。查询结果中的sample_reason可以解释为什么该条被保留。

## 历史写入：独立消费、去重与保留清理

阅读 `Sample`：先解码和验证事件，再检查实体是否属于历史采样范围、是否有snapshot以及是否超出保留时间。DELETE没有snapshot，不生成一条假的位置样本。首次处理实体会从数据库读取lastSample，不能每次进程重启都假设从未采过样。

当前投影和历史消费使用不同消费组。Redis暂时不可用不应该迫使历史和当前状态共用一个提交进度。数据库写入失败返回错误，让历史消费者重试；重复消息由唯一键处理，内存采样基线只在正确持久化后推进。

历史保存7天。`pruneHistoryPage` 做有限批量删除；`pruneHistoryBatch` 控制本轮工作量；`pruneHistory` 调度下一轮。有积压时短间隔继续清理，依赖失败时保留错误并后续重试。一次处理上限不是“只删这么多，剩下永远不管”。

## 查询分页：游标记录位置，也约束查询范围

阅读 `ListHistorySamples` 与 `internal/platform/cursor.go`。时间范围必须为正且不超过24小时，page size默认100、最大500。查询使用 `[start,end)`，结束时刻不包含在本次范围。

排序键是occurred_at加id。SQL条件的含义是：“发生时间大于上一条，或者时间相同但id更大”。每次多取一条，用它判断是否还有下一页，返回给用户仍最多page size条。

游标还包含首次查询的采样时间上界、租户、实体/时间过滤摘要及15分钟有效期，并签名。后续页不能拿同一个token换租户或换时间范围。采样时间上界用于约束翻页期间新增记录，但不承诺跨多次RPC共享一个数据库事务快照。

## 运行与预期

停止Z07进程，升级文件，然后：

```powershell
Set-Location 'D:\job\golang\projects\meshops-course-lab'
./scripts/initialize.ps1
./scripts/start.ps1 -Simulators
. ./scripts/env.ps1
$from = [DateTimeOffset]::UtcNow.AddMinutes(-10).ToString('O')
$to = [DateTimeOffset]::UtcNow.ToString('O')
./bin/opctl.exe history --entity person-001 --start $from --end $to --page-size 10
```

启动后历史消费者需要时间采样，第一次为空时稍后重新计算 `$to` 再查。应得到samples，其中包含实际发生时间、采样时间、快照和sample reason；不能要求每次网关上报都有一条历史行。

执行 `./scripts/test.ps1 -Integration` 时，历史集成测试验证真实数据库写入、分页及清理。单测的采样条件只能证明判断函数，不证明表结构、索引和消费者装配正确。结束实验执行 `./scripts/stop.ps1`。

常见问题：范围超过24小时会被拒绝，按天拆查询；token更换过滤条件或过期会被拒绝，重新从第一页开始；数据库不可用应返回错误，不把错误转成“历史为空”；只复制history.go却没有更新Entity构造会编译失败，核对完整变化清单。
