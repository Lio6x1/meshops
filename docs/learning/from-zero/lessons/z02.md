# Z02｜用 go-zero 启动第一个 Entity 查询服务

本课在 Z01 的查询协议上增加可执行代码。目标是运行两个进程：服务端持续监听，客户端发出一次查询并退出。为了先看懂请求链路，服务端只返回固定的 `person-001`，电量缺失。

**本课不连接 Redis、MySQL、Kafka、etcd，也不运行 Docker。** go-zero 通过 `zrpc.NewServer` 创建 RPC 服务，客户端通过明确地址直连。

这里没有 Etcd 配置，因此不注册服务发现。客户端下一步直接传地址即可。

## 4. 实现 GetSnapshot：输入、返回值和每条分支

新建 `internal/service/entity.go`：

<!-- source:internal/service/entity.go -->
<!-- generated-code:start -->
```go
package service

import (
 "context"
 "strings"

 commonv1 "example.com/meshops-course/gen/common/v1"
 entityv1 "example.com/meshops-course/gen/entity/v1"
 "google.golang.org/grpc/codes"
 "google.golang.org/grpc/status"
)

type EntityServer struct {
 entityv1.UnimplementedEntityServiceServer
}

func New() *EntityServer { return &EntityServer{} }

func (s *EntityServer) GetSnapshot(ctx context.Context, req *entityv1.GetSnapshotRequest) (*entityv1.GetSnapshotResponse, error) {
 if err := ctx.Err(); err != nil { return nil, status.FromContextError(err).Err() }
 id := req.GetEntityId()
 if strings.TrimSpace(id) == "" { return nil, status.Error(codes.InvalidArgument, "entity_id is required") }
 // This fixed row exists only to observe the first query round trip.
 if id != "person-001" { return &entityv1.GetSnapshotResponse{EntityId:id, Found:false}, nil }
 return &entityv1.GetSnapshotResponse{
  EntityId:id, Found:true,
  Snapshot:&commonv1.EntitySnapshot{
   EntityType:"person",
   Location:&commonv1.Location{Latitude:31.2304, Longitude:121.4737},
  },
 }, nil
}
```
<!-- generated-code:end -->

先看签名：

```go
func (s *EntityServer) GetSnapshot(ctx context.Context, req *entityv1.GetSnapshotRequest) (*entityv1.GetSnapshotResponse, error)
```

- `func` 声明函数。`(s *EntityServer)` 是接收者，表示这个方法属于 EntityServer；星号表示指针。
- `ctx` 传递本次调用的取消及截止时间；`req` 是解码后的请求指针。
- 两个返回值分别是响应指针与错误。`return reply, nil` 表示 RPC 成功；`return nil, err` 表示 RPC 失败。
- `entityv1`、`commonv1` 是 import 别名，避免两个都叫 entity 的包混淆。
- 嵌入 `UnimplementedEntityServiceServer` 满足生成接口的兼容性要求。`New()` 用 `&EntityServer{}` 创建实例，`&` 取得指针。

按实际执行顺序读方法体：

1. `ctx.Err()` 不为空，说明请求已取消或超时；转成 gRPC 状态后返回，后面不再处理。
2. 从请求取编号。生成的 `GetEntityId()` 对 nil 请求安全，返回字符串零值。
3. `strings.TrimSpace` 检测空白编号，失败返回 `InvalidArgument`。这里没有偷偷修改合法编号。
4. 编号不是固定样例 `person-001`，返回 `found=false`。这不是网络错误。
5. 否则创建新的响应和嵌套快照，返回 `found=true`。每次新建对象，避免请求之间共享可修改的指针。

`&commonv1.Location{Latitude:31.2304, Longitude:121.4737}` 是带字段名的结构体初始化。服务端没有设置 Power，所以它的 Go 零值是 `nil`，这就是“未知”，不是 0%。

本课没有仓库，也没有“修改固定样例”的接口。不要把这条固定数据当作最终存储方案。

## 5. 服务端 main：让框架调用我们的实现

新建 `cmd/entity/main.go`：

<!-- source:cmd/entity/main.go -->
<!-- generated-code:start -->
```go
package main

import (
 "flag"
 "fmt"
 "log"

 entityv1 "example.com/meshops-course/gen/entity/v1"
 "example.com/meshops-course/internal/config"
 "example.com/meshops-course/internal/service"
 "github.com/zeromicro/go-zero/core/conf"
 "github.com/zeromicro/go-zero/zrpc"
 "google.golang.org/grpc"
)

func main() {
 file := flag.String("f", "configs/entity.yaml", "path to server YAML")
 flag.Parse()
 var c config.Config
 if err := conf.Load(*file, &c); err != nil { log.Fatal(err) }
 server, err := zrpc.NewServer(c.RpcServerConf, func(g *grpc.Server) {
  entityv1.RegisterEntityServiceServer(g, service.New())
 })
 if err != nil { log.Fatal(err) }
 defer server.Stop()
 fmt.Printf("Entity listening on %s\n", c.ListenOn)
 server.Start()
}
```
<!-- generated-code:end -->

执行顺序是 `flag.String → flag.Parse → conf.Load → zrpc.NewServer → RegisterEntityServiceServer → Start`。

`flag.String` 返回字符串指针，所以读取路径要写 `*file`。`-f` 不传时用 `configs/entity.yaml`；相对路径以启动终端所在目录为准。

`var c config.Config` 先声明零值配置。`conf.Load(*file, &c)` 把 YAML 写入 `c`，所以传地址 `&c`。`if err != nil` 是 Go 常见显式错误处理。读文件失败就 `log.Fatal` 退出，不继续启动半成品服务。

`func(g *grpc.Server) { ... }` 是作为参数传入的匿名函数。go-zero 建好底层 gRPC server 后调用它，我们在其中注册生成的接口及 `service.New()` 返回的实现。**注册方法才把“协议里有这个名字”和“收到请求应该运行这个 Go 函数”连接起来。**

`defer server.Stop()` 登记函数返回时的清理。`server.Start()` 持续运行，所以终端不会立即回到提示符。启动打印是开始监听流程的提示；要确认真的可用，还必须运行客户端或 smoke 测试。

## 6. 客户端 main：一次调用后退出

新建 `cmd/query/main.go`：

<!-- source:cmd/query/main.go -->
<!-- generated-code:start -->
```go
package main

import (
 "context"
 "flag"
 "fmt"
 "os"
 "time"

 entityv1 "example.com/meshops-course/gen/entity/v1"
 "google.golang.org/grpc"
 "google.golang.org/grpc/credentials/insecure"
 "google.golang.org/grpc/status"
)

func run() error {
 addr := flag.String("addr", "127.0.0.1:50162", "server address")
 id := flag.String("id", "person-001", "entity ID")
 flag.Parse()
 conn, err := grpc.NewClient(*addr, grpc.WithTransportCredentials(insecure.NewCredentials()))
 if err != nil { return err }
 defer conn.Close()
 client := entityv1.NewEntityServiceClient(conn)
 ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
 defer cancel()
 reply, err := client.GetSnapshot(ctx, &entityv1.GetSnapshotRequest{EntityId:*id})
 if err != nil { return err }
 if !reply.GetFound() { fmt.Printf("id=%s found=false\n", reply.GetEntityId()); return nil }
 snapshot := reply.GetSnapshot()
 if snapshot == nil || snapshot.GetLocation() == nil { return fmt.Errorf("response has no snapshot/location") }
 power := "unknown"
 if snapshot.Power != nil && snapshot.Power.BatteryPercent != nil {
  power = fmt.Sprintf("%.1f%%", *snapshot.Power.BatteryPercent)
 }
 fmt.Printf("id=%s found=true type=%s lat=%.4f lon=%.4f power=%s\n",
  reply.GetEntityId(), snapshot.GetEntityType(), snapshot.Location.Latitude, snapshot.Location.Longitude, power)
 return nil
}

func main() {
 if err := run(); err != nil {
  fmt.Fprintf(os.Stderr, "query failed: code=%s message=%s\n", status.Code(err), status.Convert(err).Message())
  os.Exit(1)
 }
}
```
<!-- generated-code:end -->

`run() error` 把业务流程与进程退出分开，让 `defer conn.Close()`、`defer cancel()` 在 run 返回时先执行，然后 main 才 `os.Exit(1)`。

`grpc.NewClient` 创建连接对象；它不证明服务已经在线。真正调用 `client.GetSnapshot` 时才会连接并交换消息。`insecure.NewCredentials()` 表示本机练习使用明文传输。当前 YAML 只监听本机；生产部署的身份和 TLS 在后续范围中处理。

`context.WithTimeout(..., 3*time.Second)` 创建最长三秒的调用上下文。`cancel` 是一个函数，`defer cancel()` 用来及时释放计时资源。客户端和服务端都要有超时边界。

`reply.GetFound()` 为 false 时打印未找到并成功退出。如果为 true，却缺少 snapshot/location，客户端报响应格式错误。电量先默认 `unknown`，只有两个可选层次都存在才读取 `*BatteryPercent`。星号在这里是“取指针所指的值”，不是乘法。

`fmt.Printf` 中 `%s` 替换字符串，`%.4f` 把浮点数打印到小数点后四位，`%%` 打印一个百分号；`\n` 换行。标准输出显示业务结果，标准错误显示失败信息。RPC 错误保留 `status.Code`；本地的普通 Go 错误没有 gRPC 状态时显示 Unknown。

## 8. 两层验证：方法行为和真实网络

完整测试文件：

<!-- source:internal/service/entity_test.go -->
<!-- generated-code:start -->
```go
package service

import (
 "context"
 "testing"
 entityv1 "example.com/meshops-course/gen/entity/v1"
 "google.golang.org/grpc/codes"
 "google.golang.org/grpc/status"
)

func TestQueryContract(t *testing.T) {
 server := New()
 reply, err := server.GetSnapshot(context.Background(), &entityv1.GetSnapshotRequest{EntityId:"person-001"})
 if err != nil || !reply.GetFound() || reply.GetSnapshot().GetEntityType() != "person" || reply.GetSnapshot().Power != nil { t.Fatalf("person: %v %v", reply, err) }
 reply, err = server.GetSnapshot(context.Background(), &entityv1.GetSnapshotRequest{EntityId:"missing"})
 if err != nil || reply.GetFound() || reply.GetSnapshot() != nil { t.Fatalf("missing: %v %v", reply, err) }
 _, err = server.GetSnapshot(context.Background(), &entityv1.GetSnapshotRequest{})
 if status.Code(err) != codes.InvalidArgument { t.Fatalf("empty: %v", err) }
 ctx, cancel := context.WithCancel(context.Background())
 cancel()
 _, err = server.GetSnapshot(ctx, &entityv1.GetSnapshotRequest{EntityId:"person-001"})
 if status.Code(err) != codes.Canceled { t.Fatalf("cancel: %v", err) }
}
```
<!-- generated-code:end -->

`Test...` 开头的函数由 `go test` 识别。`t.Fatalf` 打印原因并结束当前测试。`context.WithCancel` 后立刻 `cancel()`，验证提前取消请求不会继续返回业务成功。这个测试直接调用方法，所以还不能证明端口和注册正确。

运行完整 [smoke.ps1](../starter/z02/smoke.ps1) 才启动真实服务并调用客户端：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\smoke.ps1
if ($LASTEXITCODE -ne 0) { throw 'smoke failed' }
```

脚本把二进制与日志放在 `.local/`，让操作系统选择临时端口，启动隐藏的服务进程，等查询成功后才验收，最后停止自己创建的进程。它不占用 50162，也不停止你手工运行的服务。端口从探测到绑定之间存在很小的竞争窗口；若日志显示已占用，重新运行即可。

实际 smoke 输出：

```text
id=person-001 found=true type=person lat=31.2304 lon=121.4737 power=unknown
id=missing found=false
PASS: z02 real gRPC query
```

## 9. 常见错误与下一课

| 现象 | 原因与下一步 |
|---|---|
| configs/entity.yaml 找不到 | 在本课根目录启动，或用 `-f` 指定正确路径 |
| address already in use | 上次服务还在；停止自己启动的进程，或同步改 YAML 与客户端地址 |
| Unavailable / DeadlineExceeded | 先检查窗口 A 是否还运行、地址是否一致；NewClient 成功不代表已经连接 |
| 请求一直查不到 | 本课只有精确编号 `person-001`，大小写与空格不会自动修正 |
| 误改 gen 后行为异常 | 恢复 Proto，重新执行 generate.ps1，把业务代码写回 internal/service |

本课调用链是：**query main → 生成客户端 → 网络 → go-zero 注册的服务 → GetSnapshot → 响应 → 客户端打印**。
