# Z00｜从“我想查一个对象”开始，而不是先搭中间件

本课从一张空白需求表开始。你不需要读旧项目，不需要知道 Kafka、Redis、MySQL，也不需要启动 Docker。先决定程序要回答什么，后面才有理由创建文件。

## 本课交付物：一条清楚的查询需求

假设我们有一个园区。人和无人机都在园区里移动。操作人员输入一个编号，希望查到该对象目前的位置；如果该对象上报了电量，再显示电量。

把这句话写成可以验收的约定：

| 问题 | 本课程当前约定 | 为什么 |
|---|---|---|
| 查谁？ | 用 `entity_id`，例如 `person-001`、`drone-001` | 编号唯一标识一个对象 |
| 它是什么？ | `entity_type` 为 `person` 或 `drone` | 类型描述对象，不负责标识对象 |
| 查到什么？ | 一份当前快照：类型、经纬度、可选电量 | 快照是某个时刻的状态，不是历史列表 |
| 没有这个编号？ | 返回同一编号、`found=false`、没有快照 | “没找到”是一次有效查询的业务结果 |
| 编号为空？ | 返回 `InvalidArgument` 错误 | 输入不满足接口要求，不应伪造一行数据 |
| 人没有上报电量？ | 电量缺失，客户端显示 `unknown` | 缺失不等于 0% |
| 无人机明确上报 0？ | 保留明确的 0，客户端显示 `0.0%` | 0% 是实际数值，有业务意义 |

这个阶段使用同一套 Entity 查询接口处理人和无人机。不能把“实体”默认为无人机，也不能让所有人都带着一个假的 100% 电量。人也可能携带上报电量的设备，因此我们不写“person 永远不允许 power”的限制：组件有没有值，由实际数据决定。

## 用三条数据把约定讲清楚

```text
person-001 → type=person, lat=31.2304, lon=121.4737, power=缺失
drone-001  → type=drone,  lat=31.2304, lon=121.4737, power=80%
drone-002  → type=drone,  lat=31.2304, lon=121.4737, power=0%
```

“缺失”不是字符串 `"缺失"`，而是程序中没有那个可选值。下一课用 Protobuf 的消息字段和 `optional double` 表达它。

`entity_id` 放在请求及响应外壳里；`snapshot` 里放类型和状态内容。这样，同一份状态结构以后可以被接入服务、消息事件、查询响应复用，而不用把每种网络信封都塞进快照。

## 先分清五个词

| 词 | 在这门课中的具体含义 |
|---|---|
| 客户端 | 我们自己写的一个 Go 命令行程序；它发送查询 |
| 服务端 | 另一个持续运行的 Go 程序；它接收查询并返回结果 |
| RPC | 客户端调用服务端的方法，看起来像函数调用，实际跨进程、经过网络 |
| Proto | 描述请求、响应和服务方法的接口文件；不是服务端实现 |
| go-zero | 帮我们读取配置、创建并管理 RPC 服务的 Go 框架 |

两个程序运行在同一台电脑也叫跨进程。客户端直接访问服务地址 `127.0.0.1:50162`，这里的 `127.0.0.1` 是本机，`50162` 是端口。前几课不需要服务发现。

## 为什么不在第一步就写数据库

目前的第一个问题是“请求能不能到达服务端，响应能不能回到客户端”。固定一条数据就足够证明这件事。等到要验证“写入后还能查询更新”时，再引入内存仓库。等到明确要求“进程停止后仍保留数据”时，才讨论持久化。

每一步都会给出该阶段**完整、独立的文件快照**：

| 课 | 完成后能做什么 | 本课才出现的东西 |
|---|---|---|
| [Z01](z01.md) | 把查询约定转换成可以编译的 Go 类型 | module、两个 Proto、生成脚本及生成代码 |
| [Z02](z02.md) | 启动 go-zero 服务，用客户端查到固定的一名人员 | YAML、服务实现、两个 main、查询测试 |
| [Z03](z03.md) | 临时写入人员/无人机状态，再查询、更新和重启验证 | 临时 PutSnapshot、内存 map、读写锁、写入客户端 |
| 后续课程 | 把临时写入替换为正式接入，再逐步引入事件和持久化 | 按需求逐课增加 |

仓库根目录的完整工程 是后续终点的参考答案，不是 Z01 的起点。前四课只需要 `starter/` 里的对应阶段。

## 开始写代码前，口头检查四个答案

1. 查不到对象是 `found=false`，还是服务器崩溃？答案是前者。
2. 人没有电量应该显示 0% 吗？不应该，应显示未知。
3. 一个 Proto 文件是否已经能够监听网络？不能，它只描述接口。
4. 内存写入成功是否证明重启后还在？不能，Z03 会亲自验证丢失。

本课没有要运行的业务程序，也没有隐藏的“先完成基础框架”步骤。下一课从创建一个空目录、一个 `go.mod` 文件开始。
