本课拆成 [Z12-01：协议类型、请求和状态规则](steps/z12-01.md) 与 [Z12-02：页面与交互](steps/z12-02.md)。每一步按清单创建和替换完整文件，[Z12 完整文件答案](files/z12.md) 给出全部代码。下面的片段只用于讲解，**不要求你根据片段补全遗漏代码**；复制路线以完整答案为准。

## 1. 先知道前端这几个文件做什么

浏览器不能直接执行 Go，也不会直接读取数据库。一次点击“查询任务”的过程是：Vue 处理按钮事件 → `fetch` 请求 `/api/v1/tasks` → Z11 网关调用 gRPC → Task 查询数据库 → JSON 回到浏览器 → Vue 更新表格。

| 文件 | 作用 | 初次阅读重点 |
| --- | --- | --- |
| `web/package.json`、`package-lock.json` | 定义前端依赖和命令，锁定安装版本 | `dev`、`build`、`test` 分别干什么 |
| `web/index.html` | 页面入口，提供 `#app` 容器 | 为什么不是把所有页面写在这一个 HTML 里 |
| `web/src/main.ts` | 创建 Vue 应用、路由、注册 Element Plus | 页面地址如何对应组件 |
| `web/src/App.vue` | 用户名/密码登录、导航和整体外壳 | 未登录或待改密时为什么不挂载业务页 |
| `web/src/types.ts` | 与真实 Proto JSON 对齐的数据类型 | camelCase、字符串 int64、optional |
| `web/src/transport.ts`、`api.ts` | 发送 HTTP、解释错误、维护会话内存 | cookie 与 CSRF 如何传递 |
| `web/src/domain.ts` | 新鲜度、版本、任务状态和创建请求规则 | 页面怎样避免误导操作员 |
| `web/src/accounts.ts` | 账号权限、用户名和密码输入规则 | Unicode 字符数与字节数、强制改密和管理员限制 |
| `web/src/entities.ts` | 生命周期内的一条 SSE 订阅 | 何时连接、重连、关闭 |
| `web/src/requests.ts` | 丢弃过时的查询响应 | 为什么先发请求不一定先返回 |
| `web/src/views/` | 业务页、任务详情、账号管理和个人改密 | 每个页面实际调用哪个接口 |
| `web/src/components/`、`style.css` | 共用表格、快照字段和视觉样式 | 为什么共用字段展示能减少不一致 |

`.vue` 文件通常有三部分：`<script setup lang="ts">` 写状态和函数，`<template>` 写界面结构，样式可以在组件或共用 CSS 中定义。`lang="ts"` 表示 TypeScript，它帮助发现类型错误，不会替代后端输入校验。

## 2. Z12-01：先写领域规则，再连接网络

按 [本步清单](steps/z12-01.md) 建文件。这个检查点可能尚未包含页面入口，**先执行清单要求的领域测试，不要提前运行 Vite 构建完整界面**。同一检查点的相互引用文件应全部创建后再执行命令。

### 2.1 未知电量不能显示成零

Proto 的 `optional double battery_percent` 对应：

```typescript
power?: { batteryPercent?: number }
```

外面的 `?` 表示没有整个电量组件，里面的 `?` 表示组件存在但电量值未提供。两种缺失都不能推断为 `0%`。真实提供的 `0` 则是事实。完整代码中用 `display` 判断 `undefined/null`，不用 `value || 0`。

版本和部分计数在 JSON 中是字符串，例如：

```typescript
const newer = BigInt('9007199254740993') > BigInt('9007199254740992')
```

`BigInt` 用于精确比较；保存、请求和显示仍用原字符串。不要先 `Number(version)`，否则超过 JavaScript 安全整数范围的相邻值可能变成同一个数。

普通 proto3 的非 optional 字段可能省略零值，例如已存在 `person` 组件内的 `onDuty` 缺省代表 `false`。这与“整个 person 组件不存在”不同；完整 `SnapshotDetails.vue` 分别处理这些情况。

### 2.2 HTTP 请求把错误带回来

完整实现的核心语句是：

```typescript
const response = await fetcher(path, {
  ...init,
  headers,
  credentials: 'same-origin',
})
```

1. `path` 是 `/api/...` 相对路径，不写机器令牌或租户。
2. `init` 包含方法、JSON 请求体等选项。
3. `headers` 在写请求时加入 `X-CSRF-Token`，有 JSON 请求体时声明 Content-Type。
4. `credentials: 'same-origin'` 允许浏览器携带同源 cookie。HttpOnly cookie 的内容不由页面读取和拼接。
5. `await` 等待响应，期间不会阻塞浏览器绘制其他内容。
6. HTTP 失败会抛出带 `code`、`httpStatus` 的 `ApiError`，页面分别显示错误、过期或重新登录；不能把失败当作空列表。

`api.ts` 的 `session` 只保存在内存。登录只提交 `{username,password}`，返回 `csrfToken`、角色、`username`、`displayName`、`mustChangePassword` 和时间信息；内部 RPC 令牌留在 Go 网关。页面不写 localStorage/sessionStorage，也不把密码放进 URL。密码按原文提交，在提交结束和相关组件卸载时清空。`401` 使当前会话退回登录；旧账号请求延迟返回的 `401` 不能清除新登录的会话。`403` 显示权限、强制改密或 CSRF 错误，不擅自切换为管理员。

### 2.3 查询响应也有“过时”的问题

假设先查无人机 A 的历史，又立刻点开机器人 B：B 的请求先返回，A 的请求后返回。若每个 `.then` 都直接写同一个数组，B 的抽屉会出现 A 的记录。

完整代码的 `LatestRequest` 给每次请求分配递增代次，只有最后一代能发布结果：

```typescript
const generation = ++this.generation
const value = await operation()
if (generation === this.generation) apply(value)
```

`invalidate()` 用于切换实体、修改条件和离开页面；不仅旧数据，旧错误和旧 `finally` 回调也被忽略。搜索的过滤条件、当前页和签名游标要同时固定，不能把旧查询的 cursor 接在新关键词后面。

测试 `requests.test.ts` 人工控制两个 Promise 的完成顺序，要求“新结果先到、旧结果后到”时页面仍保留新结果与新 cursor。这是在验证用户可遇到的并发问题。

### 3.1 看懂一段 Vue 交互

以列表读取为例，以下是用于理解语法的独立小片段，不覆盖完整文件：

```typescript
const tasks = ref<Task[]>([])
const busy = ref(false)

async function refresh() {
  busy.value = true
  try {
    const result = await api<{ tasks?: Task[] }>('/api/v1/tasks')
    tasks.value = result.tasks ?? []
  } finally {
    busy.value = false
  }
}
```

`ref` 创建响应式状态；脚本中通过 `.value` 访问，模板里 Vue 会自动解包。`Task[]` 表示任务数组。`?? []` 只在字段缺失时取空数组。实际页面还要 `catch` 显示读取错误，控制分页并处理定时刷新，详见完整 `Tasks.vue`。

对应按钮形状是：

```html
<el-button :loading="busy" @click="refresh">刷新任务</el-button>
```

`el-button` 来自 Element Plus；`:loading` 把状态传给组件，`@click` 绑定点击函数。框架帮你画按钮和加载效果，业务请求仍然由自己的函数决定。

### 3.2 页面与真实接口对应

| 页面 | 读取/写入接口 | 关键限制 |
| --- | --- | --- |
| 实体总览、资源 | 授权清单、SSE、历史采样 | 只订阅明确授权 ID，不把断线等同离线 |
| 任务中心、详情 | List/Create/Get/Cancel/History | 稳定幂等键，取消意图与终态分开 |
| 任务检索 | SearchTasks | 最终一致、签名游标，操作前读权威详情 |
| 可靠分发 | GetDispatch、RetryDLQ | 一次只返回最新/指定记录，人工重试仅管理员 |
| 运行状态 | GetStatus | 只显示真实三项指标与采样时间，无伪造趋势 |
| 账号管理 `/accounts` | GET/POST `/api/accounts`、PATCH 账号、POST reset-password | 仅管理员；只能创建和管理操作员，不提供账号删除或角色选择 |
| 修改密码 `/account/password` | POST `/api/account/password` | 本人提供当前和新密码；成功 204 后清会话并重新登录 |

### 3.3 SSE 的初始化与断线

`new EventSource('/api/v1/entities/stream?...')` 创建保持打开的 HTTP 连接，浏览器接收 `event: update`。`onopen` 只说明连接成功，必须等本次 `ENTITY_UPDATE_KIND_SNAPSHOT_END` 才允许依赖新鲜状态的创建操作。

阅读 `entities.ts` 和 `domain.ts` 时按顺序找：

1. 先从可信清单取 ID，最多订阅 100 个。
2. 每页建立一条连接；导航离开时 `onUnmounted` 关闭连接和时钟计时器。
3. 收到不同 `syncId` 或 `viewGeneration` 时重新初始化；不把上一个视图当作连续快照。
4. 同一同步内只接受更高实体版本，删除保留版本墓碑，晚到旧 UPSERT 不能复活实体。
5. 断线时保留最后快照并撤销“同步完成”，浏览器重新连接后等待新的结束标记。
6. 数据是否过期取决于 `expiresAt` 与校准时间，不取决于页面刚收到一条心跳。

### 3.4 创建、取消和搜索的边界

创建表单只提供 `inspect`，固定优先级 5，时长为 1—60 秒，备注最多 256 UTF-8 字节。中文字符可能占多个字节，所以使用 `TextEncoder` 计算，而不是只看字符串长度。截止时间在未来 24 小时内，服务端再次校验。

第一次提交时执行 `makeDraft`，生成一次 `crypto.randomUUID()` 幂等键并冻结完整参数。发送超时后保持该请求，点击“重试原请求”发送同一组参数。明确放弃前提醒用户原任务可能已经创建；不能通过自动换 key 让报错消失。

任务详情根据权威 `statusVersion` 避免旧响应覆盖新状态。`cancelRequested=true` 只显示“已请求取消，等待确认”，不把业务状态直接改成 CANCELLED。

搜索没有 total，因此界面只显示本页数量和下一页，不提供任意跳页。`FAILED_PRECONDITION` 的数值 `code=9` 表示当前搜索快照过期时，清除旧 cursor，保留条件从第一页重新开始。正常任务列表、搜索列表和历史采样的 cursor 各自独立。

### 3.5 按账号生命周期阅读界面代码

先完整复制 [账号规则](../../../../web/src/accounts.ts)、[账号管理页](../../../../web/src/views/Accounts.vue) 和 [改密页](../../../../web/src/views/PasswordChange.vue)，再对照 [App.vue](../../../../web/src/App.vue) 的入口；完整答案已收录这些文件，不需要自己拼接省略实现。

1. `App.vue` 恢复会话时显示加载状态，未登录显示用户名/密码表单。登录页没有操作员/管理员选择，身份来自后端返回值。
2. `canUseBusiness` 判断是否完成强制改密。`mustChangePassword=true` 时只挂载 `PasswordChange`，导航只保留改密，顶部仍可退出。即使直接输入任务 URL，也不会挂载业务组件和开启它的轮询/SSE；服务端还会独立拒绝业务请求。
3. `Accounts.vue` 仅管理员加载列表，每次请求 20 条，保存 `nextCursor`。翻页成功后再更新页码，失败显示错误并保留重试入口；使用 `LatestRequest` 拒绝旧结果、旧错误和旧收尾回调覆盖当前页面。没有总数，不伪造任意跳页。
4. 创建表单只提供用户名、显示名称、初始密码和确认密码；`canManageAccount` 限制目标为操作员。初始管理员行不显示禁用/重置按钮。启停和重置都有具体目标确认，成功后从服务端刷新列表，不仅改变本地开关。
5. `PasswordChange.vue` 检查新密码与确认一致、与当前密码不同，提交 `{currentPassword,newPassword}`。收到 204 后清会话，登录页提示使用新密码重新登录；明确失败则展示后端错误。密码输入在提交结束或页面卸载时清除。

输入检查只为及时反馈。用户名使用 3—32 位小写字母、数字、下划线或短横线；密码使用 12—128 个 Unicode 字符且不超过 512 UTF-8 字节，不自动去掉空格。真正的权限、哈希、唯一约束和会话撤销由 Z11 后端负责。操作员忘记密码由管理员重置，初始管理员恢复使用本机 CLI，不在页面添加邮箱找回或公开注册。
