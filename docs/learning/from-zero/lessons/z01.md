# Z01｜从空目录写 module 和最小 Proto

上一课确定：按编号查询人或无人机的位置，电量可以缺失。本课只把这条约定写成机器可以理解的接口，并生成 Go 文件。**本课还没有 main，不启动服务端，也不使用 Docker。**

完成标准：`go test ./...` 能编译两个生成包。输出 `[no test files]` 只表示目前没有测试函数，不表示网络请求已经验证。

## 1. 准备目录与固定工具

本课完成版本位于 [starter/z01](../starter/z01/)。你可以从空目录逐文件创建；如果复制漏了文件，用这个完整快照核对。以下命令都在 PowerShell 执行，路径包含空格时保留引号。

完整文件清单及可复制答案见 [Z01全部文件](files/z01.md)，包含go.sum、.gitignore与生成文件链接。全程使用同一个学习目录。

```powershell
$lesson = 'D:\job\golang\projects\meshops-course-lab'
if ((Test-Path $lesson) -and (Get-ChildItem -LiteralPath $lesson -Force | Select-Object -First 1)) { throw '学习目录不为空，请先选择一个新的空目录' }
New-Item -ItemType Directory -Force $lesson | Out-Null
Set-Location $lesson
$env:Path = 'D:\go1.25.10\bin;D:\my_projects\bin;D:\protoc-36.0-rc-1-win64\protoc-36.0-rc-1-win64\bin;' + $env:Path
$env:GOWORK = 'off'
go version
protoc --version
protoc-gen-go --version
protoc-gen-go-grpc --version
```

本机实测版本分别是 Go 1.25.10、protoc 36.0-rc1、protoc-gen-go v1.28.1、protoc-gen-go-grpc 1.2.0。如果你的安装位置不同，只改 PATH 中对应目录。生成器版本与运行库版本是两件事：前者负责生成文件，后者在程序运行时被 import。本课锁定的运行库为 grpc v1.83.2、protobuf v1.36.12，已实际编译通过。

若缺少 Go 插件，在已有 Go 与 protoc 的前提下执行：

```powershell
go install google.golang.org/protobuf/cmd/protoc-gen-go@v1.28.1
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@v1.2.0
$env:Path = (Join-Path (go env GOPATH) 'bin') + ';' + $env:Path
```

`go install` 第一次需要下载依赖；`@版本` 固定生成工具，避免每个人输出不同。protoc 是单独的编译器，不是上述两个 Go 插件的一部分。

## 2. 第一个文件：go.mod

在 `D:\job\golang\projects\meshops-course-lab\go.mod` 创建如下完整文件：

<!-- source:go.mod -->
<!-- generated-code:start -->
```text
module example.com/meshops-course

go 1.25.10

require (
	google.golang.org/grpc v1.83.2
	google.golang.org/protobuf v1.36.12
)

require (
	golang.org/x/net v0.58.0 // indirect
	golang.org/x/sys v0.47.0 // indirect
	golang.org/x/text v0.41.0 // indirect
	google.golang.org/genproto/googleapis/rpc v0.0.0-20260526163538-3dc84a4a5aaa // indirect
)
```
<!-- generated-code:end -->

`module` 是本工程所有 Go import 的前缀。`example.com/meshops-course` 在这里是教学模块名，不要求你真的部署这个域名。`go 1.25.10` 声明工具链最低版本。第一组 `require` 是生成代码直接使用的库；`// indirect` 表示它们是依赖链需要的库，由 Go 工具维护。

同时把完整的 [go.sum](../starter/z01/go.sum) 放在同一目录。`go.mod` 选择版本，`go.sum` 保存下载内容的校验值。它们都要保留，不能只复制两行依赖却漏掉版本锁定。

## 3. 第二个文件：共享状态 Proto

创建 `proto/common/v1/entity.proto`。从本课起，下文相对路径都相对于刚才的 `$lesson`，例如这个文件的绝对路径是 `D:\job\golang\projects\meshops-course-lab\proto\common\v1\entity.proto`。

<!-- source:proto/common/v1/entity.proto -->
<!-- generated-code:start -->
```protobuf
syntax = "proto3";

package meshops.common.v1;
option go_package = "example.com/meshops-course/gen/common/v1;commonv1";

// 快照描述状态，外层响应负责标识实体。
message EntitySnapshot {
  string entity_type = 1;
  Location location = 3;
  PowerState power = 7;
}

message Location {
  double latitude = 1;
  double longitude = 2;
}

// 缺失 power 表示不适用或未知，不表示电池耗尽。
message PowerState {
  optional double battery_percent = 1;
}
```
<!-- generated-code:end -->

逐项读这段定义：

- `syntax = "proto3"` 选择 Proto 语法；`package` 是协议命名空间，减少同名类型冲突。
- `go_package` 的分号前是生成后的 Go import 路径，分号后 `commonv1` 是 Go 包名。这两部分不是文件系统绝对路径。
- `message` 类似一张结构化数据表。生成到 Go 后成为 `struct`。
- `string entity_type = 1` 中 `1` 是线上字段编号，不是默认值，也不是数组下标。
- 本阶段只使用快照字段 1、3、7。编号留出间隙是为了与后续完整协议一致；不要为了“整齐”改成 1、2、3，已使用编号以后也不能换含义。
- `Location` 是嵌套消息，生成 Go 后通常通过指针引用；没有位置和经纬度为 0 是不同情况。本课只描述结构，Z03 才加入必填及范围验证。
- `PowerState` 消息缺失，表示没有该组件。`battery_percent` 还使用 `optional`，表示即使组件存在，也能区分“没有电量值”和“明确为零”。

将来读取电量时，必须先判断 `snapshot.Power != nil`，再判断 `snapshot.Power.BatteryPercent != nil`。仅调用 `GetBatteryPercent()` 会把缺失与明确的 0 都表现成数值 0，所以不能单靠 getter 判断是否上报。

## 4. 第三个文件：查询接口 Proto

创建 `proto/entity/v1/entity.proto`：

<!-- source:proto/entity/v1/entity.proto -->
<!-- generated-code:start -->
```protobuf
syntax = "proto3";

package meshops.entity.v1;
option go_package = "example.com/meshops-course/gen/entity/v1;entityv1";

import "common/v1/entity.proto";

service EntityService {
  rpc GetSnapshot(GetSnapshotRequest) returns (GetSnapshotResponse);
}

message GetSnapshotRequest {
  string entity_id = 1;
}

message GetSnapshotResponse {
  string entity_id = 1;
  meshops.common.v1.EntitySnapshot snapshot = 3;
  bool found = 5;
}
```
<!-- generated-code:end -->

`import "common/v1/entity.proto"` 相对于稍后命令的 `--proto_path=proto`。服务名是 `EntityService`，方法名是 `GetSnapshot`；括号左边是请求类型，`returns` 后面是响应类型。

请求只有一个参数 `entity_id`。响应含同一编号、快照和 `found`。响应字段号 1、3、5 同样保留后续协议的编号。未找到时服务端会显式返回 `found=false`，不设置 snapshot；错误请求走 RPC 错误通道，而不是把错误内容装进快照。

注意：这里没有 `PutSnapshot`。本课只为查询建模，写入需求到 Z03 才出现。

## 5. 第四个文件：生成脚本

创建 `generate.ps1`：

<!-- source:generate.ps1 -->
<!-- generated-code:start -->
```powershell
$ErrorActionPreference = 'Stop'
Set-Location $PSScriptRoot

New-Item -ItemType Directory -Force gen | Out-Null
protoc --proto_path=proto --go_out=. --go_opt=module=example.com/meshops-course --go-grpc_out=. --go-grpc_opt=module=example.com/meshops-course proto/common/v1/entity.proto proto/entity/v1/entity.proto
if ($LASTEXITCODE -ne 0) { throw 'protoc failed' }
```
<!-- generated-code:end -->

`$ErrorActionPreference = 'Stop'` 让 PowerShell 错误终止脚本。`$PSScriptRoot` 是脚本所在目录，因此从别的目录启动它也能找到 `proto/`。`New-Item -Force` 允许生成目录已存在；`Out-Null` 隐藏目录创建的格式化输出。

`protoc` 命令的参数从左到右：

| 参数 | 作用 |
|---|---|
| `--proto_path=proto` | 指定 import 的搜索根目录 |
| `--go_out=.` | 让 Go 消息生成插件把结果输出到当前工程 |
| `--go_opt=module=example.com/meshops-course` | 去掉 Go import 的 module 前缀，落到 `gen/` |
| `--go-grpc_out=.` | 生成 RPC 客户端和服务端接口 |
| `--go-grpc_opt=module=example.com/meshops-course` | 对 RPC 生成文件应用相同路径规则 |
| 最后两个文件路径 | 指定本次实际编译的两个 Proto |

外部程序返回失败时，PowerShell 不总会自动抛异常，所以还检查 `$LASTEXITCODE`，非零就 `throw`。这能避免生成失败后继续误用旧文件。

执行：

```powershell
Set-Location 'D:\job\golang\projects\meshops-course-lab'
powershell -NoProfile -ExecutionPolicy Bypass -File .\generate.ps1
if ($LASTEXITCODE -ne 0) { throw 'generate failed' }
go mod download
go test ./...
```

`ExecutionPolicy Bypass` 只用于本次子进程运行你已检查的本地脚本，不修改机器的全局策略。

应新增这些文件，全部已提供完整版本：

| 文件 | 怎么出现 | 作用 |
|---|---|---|
| [gen/common/v1/entity.pb.go](../starter/z01/gen/common/v1/entity.pb.go) | protoc-gen-go 生成 | 快照、位置、电量的 Go 类型及序列化代码 |
| [gen/entity/v1/entity.pb.go](../starter/z01/gen/entity/v1/entity.pb.go) | protoc-gen-go 生成 | 查询请求和响应的 Go 类型 |
| [gen/entity/v1/entity_grpc.pb.go](../starter/z01/gen/entity/v1/entity_grpc.pb.go) | protoc-gen-go-grpc 生成 | 客户端接口、服务端接口和注册函数 |

生成文件顶部写有 `DO NOT EDIT`。业务代码下一课写在 `internal/`；不要往生成文件里手写查询逻辑。

实际编译输出：

```text
?    example.com/meshops-course/gen/common/v1    [no test files]
?    example.com/meshops-course/gen/entity/v1    [no test files]
```

终端的空格数量可能不同。此时执行 `go run .` 会失败，因为我们确实还没创建 `package main`。

## 6. 如果想一次复制完整阶段

这是逐文件输入的替代路线，不要在已经按前文写好文件后重复执行。从空目录开始时，可以使用受管理的阶段复制：

```powershell
$Course = 'D:\job\golang\projects\meshops\docs\learning\from-zero'
$Learner = 'D:\job\golang\projects\meshops-course-lab'
& "$Course\apply-checkpoint.ps1" -Stage z01 -Destination $Learner
Set-Location $Learner
$env:GOWORK = 'off'
go test ./...
```

复制快照已含生成文件，不重新生成也能编译；学习生成流程时再执行 `generate.ps1`。手工路线在后续继续按完整文件清单创建或替换；受管理路线在后续用 `apply-checkpoint.ps1` 顺序进入下一阶段。两条路线始终使用同一个学习目录，但不要中途混用：手工创建的目录没有复制脚本所需的 `.course/checkpoint.json`。

## 7. 常见错误与下一步

| 现象 | 检查和修复 |
|---|---|
| `protoc` 无法识别 | PATH 必须指向含 protoc.exe 的 bin，而不是压缩包父目录 |
| `protoc-gen-go: program not found` | 安装插件并把 `go env GOPATH` 的 bin 放入 PATH |
| import 找不到 common 文件 | 确认目录是 `proto/common/v1/entity.proto`，从项目根目录运行脚本 |
| 下载校验/网络失败 | 先恢复正常网络，再重试 `go mod download`；不要删掉 go.sum 来跳过校验 |
| `no Go files` | 从 z01 根运行 `go test ./...`，不要执行尚不存在的 main |
| 找到父项目的依赖而不是本课 | 检查 `go env GOMOD` 指向本课 go.mod，并保持 `GOWORK=off` |

现在我们只有“合同”及其 Go 类型。下一课 [Z02](z02.md) 创建第一个服务端 main，把 `GetSnapshot` 接到真正的实现，再用第二个 main 发起查询。
