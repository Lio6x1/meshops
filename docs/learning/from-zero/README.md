## 目录分别存什么

```text
from-zero/
├── lessons/                 学生讲义：z00—z13.md
│   ├── steps/               后端与前端阶段的分步操作
│   └── files/               各阶段完整文件答案
├── exercises/              讲义明确要求运行的辅助练习
├── （最终工程位于仓库根目录，不在教材内另存一份）
├── starter/z01—z03/         前三个阶段的完整源码快照
├── state-stages/z04—z06/    状态链路的阶段源码快照
├── business-stages/z07—z10/ 任务、历史、验收与搜索阶段源码快照
├── web-stages/z11—z12/      HTTP 网关与 Vue 阶段源码快照
├── substeps/               少量阶段内过渡文件
├── verification/           教程复制、阶段运行与排错的验证记录
└── maintenance/            教师与 AI 维护说明
```

仓库根目录 `verification/` 保存早期业务验收；本目录 `verification/` 保存教程验证；`docs/verification/` 保存后续全栈、模拟器、混合压测和维护证据。各报告绑定日期与范围，不是三份当前代码。全仓用途见 [文件导航](../../README.md)。

## 为什么有相似代码

各阶段是项目在不同学习时刻的完整答案，不是同时部署的多个服务。最终实现集中在仓库根目录；阶段快照保留该阶段已经学到的能力。`lessons/files/` 再把需要新增或替换的源码展示成可复制代码块。

维护时从阶段源码生成展示代码并核对，不能把代码块和阶段文件各改一遍而不检查一致性。`.bin` 协议基线必须复制原文件，不能当文本粘贴。

## 自己写代码的位置

学生工程约定为 `D:\job\golang\projects\meshops-course-lab`，由学习步骤创建。它不在教材目录内。参考工程位于 `D:\job\golang\projects\meshops`；旧 `app/` 框架已删除，根目录即新版最终工程。

手工复制路线和 `apply-checkpoint.ps1` 管理路线二选一；默认跟随手工路线，不要在同一个学习工程混用。生成讲义、重建检查点和验收驱动等脚本属于维护工具，学生不用逐个运行。

## 当前交付范围

六类状态接入、查询/订阅、历史、四类实体的 inspect、可靠分发与恢复已在参考工程实现。当前发布包含 13 个代码阶段、28 个分步、1790 条文件指纹（Z13 为 356 个文件）和 428 个完整代码块，具体文件以 [阶段索引](checkpoint-index.json) 和 [分步索引](substep-index.json) 为准。旧阶段有连续复制记录，本次加入账号后的完整复制与构建仍在检查；构建、真实依赖与浏览器证据分别记录。学生仍须在自己的环境按课执行验收，不能以参考工程的记录代替自己的结果。

任务搜索（MySQL → Canal → Kafka → Elasticsearch）已在根工程与 Z10 实现，并配有完整答案、分步操作及搜索引导/恢复验证。Z09 保留加入搜索之前的阶段能力；阅读阶段材料时以阶段编号区分，不把 Z09 的边界理解成根工程缺失。

成品路线接在 Z10 后：Z11 加入迁移 005、Argon2id 个人账号、数据库会话鉴权、管理员 CLI 与 HTTP 网关；Z12 实现连接真实后端的 Vue 控制台、账号管理和强制改密；Z13 用 Docker Compose 统一部署并讲解本地调试、账号持久化和恢复。当前完整工程应用 001—005 增量迁移；升级 Z11 时先停止旧 Go 服务，按讲义重建、迁移并运行 Setup，不清库。各阶段完整代码清单以课程目录和对应完整文件答案为准，不要求学员从说明片段自行补全代码。复制、运行与浏览器验收由最新 [工作记录](BUILD-LEDGER.md) 跟踪。

当前工程本次普通测试、23 项必需真实依赖集成门禁、真实 HTTP 账号流程、个人任务审计/取消/CDC、30 实体场景回归及 29 项前端测试与构建已完成。最新 Windows 普通测试为 [168 PASS（unit-release）](../../../verification/2026-09-13-accounts-scale/unit-release.summary.json)，先前 Linux 普通 race 为 162 PASS；两次普通运行各有 22 项 SKIP（20 项外部依赖门控、2 项 edge/state 崩溃子进程辅助入口）；完整真实依赖 race 待最终 CI 验收，百万容量与教程最终复制验收仍待完成。规模试验是可选实验，单独控制实体基数与事件速率，并核对全部实体的预热结果；百万参数可配置不表示已经通过百万容量验证，也不表示学生已经完成该实验。

参考工程 `meshops` 本身就是独立可运行的成品；学习工程 `meshops-course-lab` 是你逐课编写的副本。可以先按 [完整启动手册](../../run-fullstack.md) 看终点，再从 Z00 学习。两个目录不要同时运行占用同一套课程端口，凭证和持久数据也不要互相覆盖。

## PowerShell 命令约定

`powershell -ExecutionPolicy Bypass -File ...` 为新进程执行脚本；设置只影响该次进程。`. ./scripts/env.ps1`（点与路径之间有空格）将环境变量加载进当前终端，两者用途不同。Z04 起需要当前终端保留数据库和 RPC 环境，所以使用点调用。

账号安全输入脚本需要 PowerShell 7（`pwsh`）。在当前 PowerShell 7 终端直接运行 `./scripts/account-admin.ps1`；不要用旧 Windows PowerShell 包装它。Docker 模式是默认值，本地课程加 `-Mode Local`，按提示设置密码，不把密码写在命令参数中。

如果可信课程脚本被本机执行策略阻止，先运行 `Get-ExecutionPolicy -List` 查看限制；普通个人学习环境可在当前终端执行 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` 后继续。它不会永久修改系统策略，关闭终端即失效；企业组策略限制须按企业规则处理。不要将秘密环境变量输出到截图或日志。

修改协议所需工具见根工程 [协议工具与基线说明](../../../testdata/proto/README.md)。显式完整依赖验收使用 `./scripts/test.ps1 -Integration`；支持 CGO/C 编译器的环境可加 `-Race`，Linux CI 对全部依赖路径执行 race。普通无依赖测试中的 Skip 不代表集成能力已验收。

## 代码注释语言

手写实现、测试、协议和启动脚本的解释注释统一使用中文，重点说明作用、原因、边界和失败处理。函数名、字段名、协议名等保留原标识符，方便对照代码。后续新增与修改代码遵守同一约定。

生成器自带的英文说明、`//go:build` 等工具指令按工具要求保留，不手工翻译。Proto 中的中文说明通过生成器同步到 Go 文件。日志和错误字符串属于运行时行为，不能当作注释直接替换。
